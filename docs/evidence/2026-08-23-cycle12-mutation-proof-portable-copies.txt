# Cycle-12 mutation proof - portable target-owned copies and the readiness guards
# Digests are bound by MutationProofBindingTest: change a graded file
# without re-running this proof and the suite fails. Paths are repository-relative.
#
# Supersedes 2026-08-23-cycle11-mutation-proof-portable-copies.txt, which is
# preserved unedited. Reason: a second independent Codex review of PR #6
# returned repairs_requested with seven findings, one of them a P0. All seven
# were repaired in one batch, changing scripts/assess_clients.py,
# scripts/check_repo.py and scripts/check_compatibility_matrix.py, so the
# cycle-11 digests no longer name the shipped bytes. Every cycle-11 anchor is
# retained and re-run against the repaired bytes rather than assumed to hold.
#
# READ THIS BEFORE COMPARING THE NUMBERS TO CYCLE 11. Cycle 11 reported 38
# mutations and 0 survivors. That number did not mean what it said, and neither
# did the equivalent number in any earlier cycle that graded these five files.
#
#   Every mutation edits a graded file. MutationProofBindingTest hashes the
#   graded files and compares them to the digests published in the current proof.
#   So every mutation failed that test -- not because the mutation broke a guard,
#   but because it changed a byte. The runner counted any failing suite as a kill,
#   which made every mutation a kill by construction. The proof was measuring its
#   own bookkeeping.
#
#   This run excludes that test from grading entirely, at baseline and under every
#   mutation. Re-graded that way, seven of the cycle-11 anchors had no test behind
#   them at all:
#
#     * the per-client package copy is unconditional -- unreachable in normal flow
#       only because allocate_run_directory hands out a fresh directory, so it
#       could have been deleted and nothing would have failed;
#     * the transcript is created 0600 -- redundant with the chmod that follows it,
#       which leaves the same final mode, so only the write *window* differs;
#     * a client that changed its package copy is not classified -- provably
#       redundant: invalidation rewrites every stage to blocked two statements
#       earlier, and propose_status over all-blocked already returns "unsupported";
#     * the assessment plan substitutes the package name it already knows;
#     * a safety field must be *stated* -- redundant with the emptiness check that
#       refuses the same descriptor, so only the diagnostic differs;
#     * a version-2 stage must record per-command statuses -- the entire rule
#       shipped with no test of any of its three branches;
#     * the repository gate calls the descriptor check -- check_port_descriptors
#       had tests and the one line wiring it into check_repo had none.
#
#   Sixteen tests were added for these. Where a guard turned out to be genuinely
#   redundant, the test pins what it actually contributes rather than pretending
#   it is load-bearing: the transcript test neutralizes the chmod to observe the
#   creation mode, and the descriptor test pins the difference between "you left
#   the field out" and "you wrote an empty list". The mutated-copy conditional had
#   no distinguishable contribution, so its anchor was retired with the reason
#   recorded and replaced by one naming the rewrite that does the work. Two more
#   anchors were added for validator branches that had no coverage: the version
#   gate, and the check that `command` agrees with commands[0].
#
# The guards this round added, each with an anchor here:
#   * the real-binary override is taken from the operator and never inferred,
#     because the previous repair - reject a PATH entry that is the same file
#     as the wrapper - was satisfied by a second copy of that wrapper;
#   * the process group is signalled by the child's own pid rather than looked
#     up, so cleanup still runs when the session leader has already exited;
#   * every run claims its own numbered directory and every client's package
#     copy is unconditional, so a reused --workspace cannot hand the next run a
#     copy an earlier client installed into;
#   * a declared assessment entrypoint the package does not carry is refused by
#     the repository gate and by the harness;
#   * the transcript is carried through both failure paths - the deadline and
#     the mutated-copy refusal - rather than dropped exactly when it is needed;
#   * the transcript file is created 0600 through os.open, so raw client output
#     is never briefly world-readable;
#   * a version-2 stage is graded from `commands` alone, so one unsafe command
#     is reported once rather than twice.
#
# Two further disclosures, both about whether this evidence can be trusted:
#
#   1. The runner used to require a fully green baseline. It cannot have one:
#      MutationProofBindingTest asserts the published proof names the bytes that
#      ship, and this run is what computes those digests, so it necessarily fails
#      until this run is published. The first attempt at this pass reached a green
#      baseline by editing three digests in the cycle-11 file to match the current
#      bytes - the cycle-7 defect that test exists to catch, reintroduced by the
#      tooling meant to satisfy it. That edit was reverted, cycle-11 ships
#      unedited, and the runner now grades on added failures instead.
#
#   2. That first attempt also aborted after thirty-one minutes on an ambiguous
#      anchor: the eight-space excerpt naming the transcript append is a substring
#      of the twelve-space call the deadline-path repair added. A pre-flight pass
#      over every anchor then found a second unusable one the aborted run had not
#      reached, matching nothing at all because the duplicate-grading repair had
#      restructured that loop. Both were rewritten to name their guard in its
#      current form and the whole set re-run. A partial pass is not published.
