### 1 — A failing second entrypoint reads as working (P1)

`run_stage` runs every entrypoint and records every exit status in the evidence *text*, but sets
`StageOutcome.returncode` to `statuses[0]`. `propose_status` reads that single value.

Probe: a two-command stage whose first command exits 0 and second exits 7 returns
`result=executed`, `returncode=0`, and `propose_status` proposes `works-directly`.

This is the exact silent-green the harness's own docstring claims to prevent — "the pilot shipped
a package whose two clients both failed at import, and a stage that checked one of them would have
reported that package as working." The code checks both and then reports one.

### 2 — Recorded commands are corrupted (P1)

`redact()` substitutes every placeholder value back, including the bare package name, longest
value first. A real invocation command comes back as

```
<package>/skills/<plugin-name>-network/scripts/<plugin-name>_network_client.py --help
```

The recorded command is what lands in a public evidence document. The committed matrices record
`<package>/skills/unifi-network/scripts/unifi_network_client.py`, so this both breaks the
established evidence shape and misdescribes what ran.

### 3 — An unresolved install id becomes a false package failure (P1)

`assess()` seeds `PLUGIN_ID` with `config.name`. Two clients generate their own install id at
placement and the harness captures it from that stage's output. When the capture misses, the
placeholder silently resolves to the package name, the invocation runs a path that does not
exist, the interpreter exits non-zero — and with finding 1 repaired, `propose_status` would then
propose `failed`.

Probe: Grok's invocation resolves to `.grok/installed-plugins/unifi/…`, which is never where that
client installs.

A false failure attributed to the package is the same class as the superseded Cursor row, which
recorded a package failure for what was actually an isolation artifact.

### 4 — Credential prefixes carry no shipped-descriptor guard (P2)

`credential_variables` returns `[]` when a descriptor declares no prefixes, so nothing is
stripped. `package_scripts` has exactly this guard in `tests/test_port_config.py`;
`credential_prefixes` does not, though it is the field that keeps the operator's real credentials
out of every assessment subprocess.

### 5 — `sys.path` grows per call (P3)

`check_port_descriptors` inserts unconditionally while every other module guards the insert.
Five calls grew `sys.path` from 10 to 15 entries.

### 6 — The handed-over copy is never re-fingerprinted (P3)

The committed method fingerprints the *scratch copy* before and after, which is what proves no
client added a vendor artifact to the package. The harness fingerprints only the source tree,
which no client can reach.
