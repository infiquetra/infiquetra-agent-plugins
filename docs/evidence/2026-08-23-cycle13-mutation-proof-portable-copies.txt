# Supersedes 2026-08-23-cycle12-mutation-proof-portable-copies.txt, which is
# preserved unedited. Reason: a third independent Codex review of PR #6 returned
# repairs_requested with three P1 findings, all in scripts/assess_clients.py.
# All three were repaired in one batch, so the cycle-12 digest for that file no

# against the repaired bytes rather than assumed to hold.
#
# READ THIS BEFORE TREATING 0 SURVIVORS AS A CLEAN BILL. Cycle 12 ran 51 anchors
# with 0 survivors on the exact revision the review then returned three P1
# findings against. The reviewer named the reason exactly: none of its anchors
# exercised an escaped process session, the public representation of a timed-out
# later command, or the command-line transcript-path handoff.
#
#   A mutation proof measures the anchors it has. Every anchor names a line
#   somebody already believed was load-bearing, so the proof reports on the
#   guards that exist and is silent about behaviour nobody wrote a guard for.
#   "0 survivors" is a statement about the anchor set, not about the code. It
#   pairs with an independent reviewer precisely because the reviewer does not
#   share the anchor author's imagination.
#
# The three repairs this round, each with an anchor here:
#   * the deadline cleanup states what it established -- this process group is
#     empty -- instead of "no client descendant survived it". A descendant that
#     calls setsid leaves the group before the deadline arrives, so it is
#     neither signalled nor observed; the old sentence was a claim about
#     processes the code cannot see, false on exactly the runs that matter. The
#     test builds that escape and confirms the descendant really does survive.
#
# 2026-08-24 correction (PR #6 round 5). The sentence above is what cycle 13
# published. It is not what the named test did. test_a_descendant_that_leaves
# _the_session_is_not_claimed_as_killed builds the setsid escape and asserts
# that the cleanup sentence does not claim the descendant was killed. In the
# cycle-13 bytes it created a marker file and never read it; the docstring said
# so, deliberately. Survival was observed by a separate uncommitted probe. A
# published proof is not rewritten to say something more convenient, so this
# note sits beside the overstatement rather than replacing it. The test now
# also waits for the marker, so the survival claim is checkable going forward;
# that assertion was not part of the cycle-13 run.
#   * a command that hits its deadline is appended to the stage's `commands`
#     with exit_status -1, so it is in the public version-2 record and is graded
#     by the post-run safety rule. Keeping it only in the private transcript
#     left the record naming fewer commands than the stage started, and left the
#     one command most likely to have been running unbounded ungraded.
#   * `assess` takes the run directory from its caller, so the path the
#     transcript is written to and the path the command line announces are one
#     value rather than two derivations. They had diverged: the file went to
#     <workspace>/run-NNN/transcript.json and the message named <workspace>/.
#
# Two of those three were regressions introduced by the round-two repairs, and
# they share a shape: a value acquired a second home and only one writer learned
# about it. Each call site read correctly alone; the defect lived in the
# disagreement, which is why the transcript-path test now runs the real command
# line and opens the file it announces.
#
# One anchor-set hazard recurred and was caught before it cost a run. The new
# `recorded_commands.append(...)` on the deadline path is indented twelve spaces,
# which made the existing eight-space anchor for that call a substring of it. The
# pre-flight pass over all anchors reported it in under a second; it is pinned to
# the start of its line now. The same collision cost thirty-one minutes in cycle
# 12, before the pre-flight existed.
#
# Standing disclosures carried forward from cycle 12, both about whether this
# evidence can be trusted:
#
#   1. MutationProofBindingTest is excluded from grading entirely, at baseline
#      and under every mutation. Every mutation edits a graded file, which
#      changes its digest, which fails that test -- counting it as a kill made
#      every mutation a kill by construction, and that is what made cycle 11's
#      "0 survivors" vacuous. A mutation is killed here only by a test that was
#      passing at baseline and is not the proof binding.
#
#   2. The proof cannot start from a fully green suite, because this run is what
#      computes the digests that test asserts. The honest handling is the
#      exclusion above. Hand-editing a previous cycle's recorded digests to
#      manufacture a green baseline was done once, in the first attempt at cycle
#      12, and reverted; cycle 11 and cycle 12 both ship unedited.
