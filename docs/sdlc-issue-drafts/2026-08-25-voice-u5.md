### Objective

Return the transcribed text into the bound agent's pane unsubmitted and editable —
and refuse audibly when that agent is blocked on a human decision.

**Unit U5 · lane G3 · depends on U1, U2 (sticky binding), U3 (audible refusal), U4 (transcript).**
**Requirements owned: R16, R17, R18, R19.** These requirements belong to this unit alone; no
other unit in the run implements them.

Parent contract: infiquetra/infiquetra-agent-plugins#27

### Intent

**Delivery mechanism, corrected against the installed Herdr CLI.** `herdr agent
send-keys` accepts *logical key names only* (its own help names `esc` as the canonical
Escape key), so it cannot carry arbitrary transcript text. The supported path is two
steps:

1. Resolve the sticky-bound agent with `herdr agent get <agent>` and read its
   `pane_id`.
2. Deliver the transcript with `herdr pane send-text <pane_id> "<text>"`, which sends
   literal text **without Enter**.

That `send-text` does not submit is proven by the CLI itself: its help points to
`herdr pane run <PANE_ID> <COMMAND>` as the variant that "sends text and Enter in one
call". Literal text without Enter is exactly R16's unsubmitted, editable requirement.
Never use `herdr pane run` for transcript delivery — it submits.

The bound agent is the only permitted delivery target (R17); there is no broadcast, no
fallback target, and no most-recent-speaker inference.

Speech is never an approval channel. When the bound agent is blocked on a permission,
approval, or other human-decision prompt, keystrokes are choices rather than text, so
`voice` refuses to insert or submit and **states the refusal audibly** through U3's
speak path (R18). A refused transcript is retained only transiently until the operator
explicitly uses or discards it; it is never delivered automatically and never queued
for automatic delivery (R19).

**Stated residual, preserved deliberately.** The blocked-state check is not atomic:
`voice` checks state and then delivers, and the agent can become blocked in between.
This narrows the exposure rather than eliminating it. Closing it fully would need a
guard inside the Herdr delivery command, which belongs to Herdr as a proposed
enhancement — not to `voice` as workaround machinery. Do not build that workaround
here.

**Proportionality.** `voice` is a private, single-user developer plugin — not a
Pentagon system. Prefer the smallest compatible implementation. Standard-library
Python at the repository floor of `>=3.12`, tested with `unittest` (R31). Do not add
enterprise, multi-tenant, internet-scale, high-availability, regulatory, or overly
defensive machinery without an explicit requirement or a demonstrated failure.

Do not relax real boundaries in the name of that smallness: credential handling, shell
execution, filesystem writes, Git operations, privacy and retention, destructive
actions, and production safety all keep their full strength.

**Board ownership.** The coordinator is the sole Operations-board writer. This unit
never writes board state; it produces commits, a pull request, and a typed review
outcome, and the coordinator moves the card.

### Out-of-scope / non-goals

- Direct clipboard injection, AppleScript automation, client-specific injection, or
  raw-terminal writes outside the supported Herdr commands. The supported
  `herdr pane send-text` path is explicitly permitted and is the required mechanism.
- `herdr pane run` for transcript delivery, because it appends Enter and submits.
- Auto-submitting on the operator's behalf under any circumstance.
- Queuing, retrying, or replaying a refused transcript.
- Modifying Herdr or vendoring any part of it (R15).

**Shared-surface rule.** This unit writes only the files listed below. If it concludes
it must edit a file owned by another unit, it stops and raises the conflict on the
parent contract rather than editing across the boundary.
