### Objective

Prove the full conversational loop works end to end, record the evidence, verify the
README truth U1 authored, and write the run's journal entries.

### Intent

Version one is accepted only when the full loop works, the multi-session silence check
passes, and each safety behaviour has been manually verified (R33). This unit produces
that evidence rather than asserting it.

The loop under test is the product requirement in full: a bound Herdr-managed Claude
session speaks its completed `Stop`-hook response after Markdown cleanup with fenced
code-block contents omitted; the operator toggles recording; a hosted provider
transcribes; and the text returns to that same bound session's pane through
`herdr pane send-text`, unsubmitted and editable.

Record each of the eight acceptance examples (AE1–AE8) with what was actually observed,
including AE1's multi-session silence check — with at least two Claude sessions running,
exactly one speaks.

**README: verification, not implementation.** U1 owns and implements R30. This unit
*verifies* that the README still states plainly that the package carries no provenance
manifest and no port descriptor, and preserves that truth while finalizing the document.
If the statement drifted, that is a finding against U1's merged work, not a licence for
this unit to re-own R30. The exact-once requirement ownership across R1–R33 is
unchanged: R30 belongs to U1 alone.

**This unit is the sole writer of the engineering journal for this run.** Both journal
files are newest-first inserts, so a second writer would guarantee a conflict and
displace every line anchor below the insertion.

**Proportionality.** `voice` is a private, single-user developer plugin — not a
Pentagon system. Prefer the smallest compatible implementation. Standard-library
Python at the repository floor of `>=3.12`, tested with `unittest` (R31). Do not add
enterprise, multi-tenant, internet-scale, high-availability, regulatory, or overly
defensive machinery without an explicit requirement or a demonstrated failure.

Do not relax real boundaries in the name of that smallness: credential handling, shell
execution, filesystem writes, Git operations, privacy and retention, destructive
actions, and production safety all keep their full strength.

**Board ownership.** The coordinator is the sole Operations-board writer. This unit
never writes board state; it produces commits, a pull request, and a typed review
outcome, and the coordinator moves the card.
