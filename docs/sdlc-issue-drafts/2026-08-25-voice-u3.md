### Objective

Turn the completed assistant response into speech through the declared
text-to-speech provider, after Markdown cleanup and with fenced code-block contents
omitted entirely.

**U5 depends on this unit**: R18's refusal must be *audible*, so the blocked-state
refusal in U5 speaks through this speech path.

**Unit U3 · lane G2 · depends on U1.**
**Requirements owned: R5, R6, R7.** These requirements belong to this unit alone; no
other unit in the run implements them.

Parent contract: infiquetra/infiquetra-agent-plugins#27

### Intent

`voice` speaks exactly the text Claude supplies through `last_assistant_message`. It
applies no length gate, no ceiling, no truncation, no truncation notice, no sentence
parsing, and no summarisation (R5). Version one keeps no authorship layer between
Claude's text and speech.

Basic Markdown cleaning keeps formatting syntax from being read aloud (R6), and the
contents of fenced code blocks are omitted entirely rather than summarised or spoken
(R7).

Synthesis runs through the provider the operator declared in U1. Operator decision D1
is settled: the first text-to-speech acceptance proof uses `/usr/bin/say` with egress
class `on-device`. It is a declared provider like any other — `voice` still ships no
implementation and still refuses by name rather than substituting.

Playback must expose a stop handle so U6 can interrupt it immediately, and a speak
entry point U5 can call for the audible refusal. This unit provides both mechanisms;
U6 binds the key and U5 calls the refusal.

**Proportionality.** `voice` is a private, single-user developer plugin — not a
Pentagon system. Prefer the smallest compatible implementation. Standard-library
Python at the repository floor of `>=3.12`, tested with `unittest` (R31). Do not add
enterprise, multi-tenant, internet-scale, high-availability, regulatory, or overly
defensive machinery without an explicit requirement or a demonstrated failure.

Do not relax real boundaries in the name of that smallness: credential handling, shell
execution, filesystem writes, Git operations, privacy and retention, destructive
actions, and production safety all keep their full strength.

**Board ownership.** The coordinator is the sole Operations-board writer. This unit
never writes board state; it produces commits, a pull request, and a typed review
outcome, and the coordinator moves the card.

### Out-of-scope / non-goals

- The stop key and barge-in bindings themselves — U6 owns the pane controls.
- Deciding when to refuse — U5 owns the blocked-state policy; this unit only speaks.
- Recording or transcription — U4 owns the listen path.
- Any response-length management, which the requirements exclude outright.
- Shipping a text-to-speech implementation; providers are declared, never bundled.
