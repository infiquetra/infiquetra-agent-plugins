### Objective

Turn the completed assistant response into speech through the declared
text-to-speech provider, after Markdown cleanup and with fenced code-block contents
omitted entirely.

**Unit U3 · lane G2 · depends on U1.**
**Requirements owned: R5, R6, R7.** These requirements belong to this unit alone; no
other unit in the run implements them.

Parent contract: infiquetra/infiquetra-agent-plugins#27

### Intent

`voice` speaks exactly the text Claude supplies through `last_assistant_message`. It
applies no length gate, no ceiling, no truncation, no truncation notice, no sentence
parsing, and no summarisation (R5). This is deliberate and was reaffirmed against the
ideation: version one keeps no authorship layer between Claude's text and speech.

Basic Markdown cleaning keeps formatting syntax from being read aloud (R6), and the
contents of fenced code blocks are omitted entirely rather than summarised or spoken
(R7).

Synthesis runs through the provider the operator declared in U1. A missing or
misconfigured provider produces a named refusal, never a substitution.

Playback must expose a stop handle so U6 can interrupt it immediately; this unit
provides the mechanism, U6 binds the key.

**Proportionality.** `voice` is a private, single-user developer tool. Prefer the
smallest compatible implementation. Standard-library Python at the repository floor
of `>=3.12`, tested with `unittest` (R31). Do not add multi-tenant, high-availability,
regulatory, or over-defensive machinery. Do not relax credential, shell, filesystem,
Git, privacy, destructive-action, or production-safety boundaries.

### Out-of-scope / non-goals

- The stop key and barge-in bindings themselves — U6 owns the pane controls.
- Recording or transcription — U4 owns the listen path.
- Any response-length management, which the requirements exclude outright.
- Shipping a text-to-speech implementation; providers are declared, never bundled.
