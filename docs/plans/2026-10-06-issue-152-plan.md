# Review tools for Python, CDK, shell, workflows and Markdown (issue #152)

## Summary

Add the Python, CloudFormation and Cloud Development Kit (CDK), shell, GitHub workflow, and Markdown adapters to the review-tool runner issue #151 shipped and issue #191 hardened. Each tool runs at one pinned version. Each result is a review record whose row and outcome are the ones issue #152 names. The build loop still does not call the runner.

---

## Problem Frame

Issue #152 is card C4b of the saga review redesign (parent issue #147). It implements the Python, CloudFormation and CDK, shell, workflow, and Markdown rows of the program design's "Default tools" table, mapped onto the four lens tables, including the outcomes the operator set on 5 October 2026 for findings those tables do not name.

The runner in `plugins/saga/scripts/review_tools.py` already keeps a line finding only on an added or modified line, compares a whole-project result and every type checker base against head, and writes records with no severity filled in. `plugins/saga/scripts/review_formula.py` already has a row for every outcome this card needs. What this branch does not have is an adapter for any tool in the issue's table. `plugins/saga/scripts/review_calibration.py` is not in the tree. The build loop still classifies `ruff` and `mypy` as repository-specific, which issue #151's plan left for this card.

Issue #191 is the runner this card builds on. The commit under review is untrusted. Pins, rules, the test command, and the coverage report come from the base commit. Adapters scan a detached worktree of the head commit. They take settings from the base commit and from this plugin, and they do not read a tool's settings file out of the reviewed tree.

---

## Requirements

Requirements are grouped by concern. R-IDs run continuously. AC-n is the nth checkbox under the issue's Acceptance criteria.

**Adapters and outcomes**

- R1. Every tool in the issue's table has one adapter. A record it emits carries the row or rule and the outcome in that table, and the record passes `plugins/saga/scripts/review_records.py` (AC-1).
- R2. mypy compares base and head over the whole project. A type error the change causes in a file the diff did not touch is kept, and its computed severity is blocks (AC-2).
- R3. A pip-audit vulnerability that osv-scanner also reports takes osv-scanner's score and becomes one finding. A vulnerability no tool scores is `security.dependency-high` and blocks unless a builder reason of kind `scanner-false-positive` is recorded. cdk-nag errors block and its warnings are fix later. A Checkov finding blocks only when its rule id is on the curated list. zizmor's medium and low findings are fix later (AC-3).
- R4. ruff's rule families and actionlint's rule kinds map to error, warning, or style. cfn-lint and ShellCheck map by the tool's own level through the runner's existing level rules. markdownlint-cli2 and cspell are notes. A lychee broken link is fix later (AC-4).
- R5. cosmic-ray mutates changed lines only, stops at the review's 15-minute cap, and records unfinished work as a degraded input on `testing.surviving-mutant` (AC-5).
- R6. A pytest-randomly failure and a pytest-socket failure are fix later. ruff format and shfmt write no review record (AC-6).
- R7. A CDK application that does not apply cdk-nag produces a degraded input for the cdk-nag row (AC-7).

**Pins, the write-up, and the suite**

- R8. `plugins/saga/references/review-tools.md` carries the outcome table and each adapter's level mapping and curated list, for the operator's lens sittings in card C7 (AC-8).
- R9. The default tool list holds an exact default version for every tool in the issue's table (AC-9).
- R10. The fingerprinted component list names this card's adapter modules. The list is `review_tools.FINGERPRINT_COMPONENTS`. If `plugins/saga/scripts/review_calibration.py` exists when this card is implemented, that file names the same paths. This card does not create that file (AC-10).
- R11. `python3 -m pytest plugins/saga/tests -q --import-mode=importlib` passes, and the new tests make no network call (AC-11).
- R12. The changelog records the adapters. The shipping commit also records the pin decision and the settings decision in the engineering journal, because `AGENTS.md` requires that journal when a decision ships.

## Key Technical Decisions

Each entry is the decision, then why, including the rejected alternative.

- **KTD1. The runner gains the fields these adapters need, and the new modules are imported only when a run asks for the default list.** `ScanContext` gains `base: str = ""` (the resolved base commit) and `test_command: str = ""` (the Python test command from the base profile when that language names one, otherwise `functional_test_environment.test_command`). `Adapter` gains `version_argv: tuple[str, ...] = ()` and `narrow_env: bool = False`. When `version_argv` is non-empty, `_read_version` runs that vector instead of `[tool, *version_args]`. Empty means today's probe. When `narrow_env` is true, `_execute` runs that adapter with the relocated run's allow-list (`PATH`, `LANG`, `LC_ALL`, `LC_CTYPE`, `TZ`, and fresh `HOME`, `TMPDIR`, `TMP`, `TEMP`) and deletes those directories afterwards. The version probe stays on the operator environment, because it does not execute the commit. `default_adapters()` concatenates the five new modules after the every-language adapters, importing them inside the function, not at import. `FINGERPRINT_COMPONENTS` gains the five module paths. A `ToolGap` raised from `parse` is recorded the same way as one raised from `invoke`, so a synthesis that produced no nag report can still degrade after the process exits. Rejected: leaving the modules unplugged because `review_tools.py` is not on the issue's file list. `default_adapters()` is the plug the runner already documents, and without `base` the cosmic-ray git filter cannot see the review's base commit. The existing tests that pin the fingerprint tuple and the catalogue labels are updated in the same units, or AC-11 fails. The schema, the validator, the diff reader, the two filters, the coverage parser, and the 15-minute cap are not edited.
- **KTD2. One adapter id per tool, and two ids for Checkov.** Checkov on synthesized templates is `checkov-cdk` with comparison `base-head`. Checkov on hand-written templates is `checkov-cfn` with comparison `lines`. Both use tool `checkov`, the same pin, the same curated list, and the same parser. A repository with no `cdk.json` makes `checkov-cdk` return no argument vector, so it does not run and does not degrade. Rejected: one Checkov adapter. The runner stores one comparison on the adapter, and a line filter would drop a CDK finding whose template line is not in the source diff.
- **KTD3. Adapters cite rows that already exist. They do not hand in a severity.** The parser sets `hit.row` when the lens table names the row, or sets `hit.level` and leaves `row` empty so `_row_for` uses `level_map` and then `review_formula.tool_row`. A builder excuse is the existing reason kind on that row. The formula turns an excused block into a note. Tests copy the two-run pattern in `plugins/saga/tests/test_review_adapters_all_languages.py` (`test_an_unscored_advisory_blocks_unless_the_builder_excuses_it`): the first run's finding id is the builder reason's `finding_id`. Rejected: new row ids. Every outcome in the issue's table is already a row in `review_formula.ROWS`.

- **KTD5. A settings file in the reviewed tree is not an input, and an inline silence does not hide a finding.** ruff is started with `--isolated`, `--ignore-noqa`, and `--select ALL`, so it does not read `pyproject.toml` or `ruff.toml` and it does not honor `# noqa` or `# ruff: ignore`. bandit is started with `--ignore-nosec` and a config the adapter wrote under the runner's home whose skip list is empty. ShellCheck is started with `--norc` on a copy of the scripts whose `# shellcheck disable` directives have been removed. mypy, cfn-lint, markdownlint-cli2, cspell, actionlint, zizmor, and Checkov are pointed at a directory or a config the adapter wrote under the runner's home, or at a copy of the source that contains no settings file. A dictionary or ignore-list that is part of the tool's configuration is taken from the base commit, written under that home, and passed as an explicit argument. The head copy is not passed. The runner's comment list also records a changed line that contains `noqa`, `nosec`, or `shellcheck disable` as a degraded input, the same way it already records `gitleaks:allow`. The file is not rewritten. One test per family plants a suppressing config in the tree the tool would scan and asserts the fixture finding is still reported. Rejected: leaving the silence comments in force. A reviewed change could then switch off bandit, ruff, or ShellCheck and count as clean.
- **KTD6. A security-tool record cites the rule and the location, not the source line.** bandit drops the `code` field. zizmor drops the snippet. Checkov and cdk-nag drop the resource body. The statement is the rule id plus the tool's short summary, and for zizmor the confidence word from `determinations.confidence`. The anchor is the rule id and the path. The raw bytes stay in the runner's content-addressed file. A fixture plants `EXAMPLE_NOT_A_SECRET` in the excerpt field and the four output files must not contain it. Rejected: a new schema field for confidence. Card C1's finding schema is closed.
- **KTD7. zizmor runs offline and receives no GitHub credential.** The argument vector includes `--offline` and `--format=json`. It does not include `--gh-token`, and it does not read a token from the environment on the adapter's behalf. Offline mode still reports an unpinned action, which is the lens-table example. Network audits are not run and are not a separate degraded input. Rejected: forwarding the operator's GitHub sign-in. The commit under review is untrusted, and a token is not a setting this review needs for the row the issue names.
- **KTD8. The four test-suite tools load with `uv run --with`, for that invocation only, and the three that execute tests use the narrowed environment.** cosmic-ray, pytest-randomly, and pytest-socket each start as `uv run --with <name>==<pin>` plus the base profile's test command, with `narrow_env` true. Nothing writes `pyproject.toml` or `uv.lock`. Every invocation except the pytest-randomly adapter passes `-p no:randomly`. Only the pytest-socket adapter passes `--disable-socket`. When `test_command` is empty, all three raise `ToolGap` with reason `known-gap` on their row, which is the same signal the relocated run already uses. Rejected: adding the packages to this repository's environment. The card's planning note forbids editing the repository to load them. Rejected: leaving these three on the operator environment. The reviewed tests would then be able to read cloud and GitHub credentials.
- **KTD9. coverage.py stays the adapter issue #151 shipped.** This card sets that row's `default_version` and does not add a second parser. Branch measurement remains the reader's existing rule: a report without branch data is reason `no-branch-data` and cannot block. The command card C3 will record, so the relocated directory receives `coverage.json`, is `uv run --with coverage==7.16.2 python -m coverage run --branch -m pytest -p no:randomly …` followed by `coverage json -o coverage.json` in that same directory. This card does not wrap the relocated command. Until C3 records it, a missing report stays reason `no-report`. Rejected: a coverage adapter with a non-empty `tool`. The runner would then execute it and also read the relocated report.
- **KTD10. cosmic-ray's git filter is pointed at the review's base commit, and the cap is the runner's.** The adapter writes its TOML under the runner's home, never into the worktree. `cosmic-ray.filters.git-filter.branch` is `context.base`. The stock filter diffs the worktree against that commit, so a line the review did not change is not mutated. `mutation` is true and `timeout_seconds` is 900, so the runner's remaining cap is the process timeout. The wrapper prints JSON `{"unfinished": bool, "survivors": [...]}`. `unfinished: true` is the runner's reason `cap`. A kill by the runner is reason `timeout`. Both are degraded inputs on `testing.surviving-mutant`. The line filter still drops a survivor whose line is not in the diff. Rejected: mutating the whole tree and relying on the line filter alone. The cap would be spent on unchanged lines, which the issue forbids.
- **KTD11. cdk-nag is a synth of the commit, and a missing report is a degraded input.** The adapter runs `cdk synth` with an output directory under the runner's home, no `--profile`, and no credential argument. `narrow_env` is true, so the process does not receive the operator's credential variables or home directory. `checkov-cdk` uses the same narrowed environment when it synthesizes. Findings are read from the synthesized template on standard output, or, if a probe during implementation shows cdk-nag writes them only to a file or to standard error, from a `python3` argument vector that prints one JSON document. A tree with no `cdk.json` returns no argument vector. A tree with `cdk.json` whose synth produces no nag report raises `ToolGap("known-gap", "security.workflow-infra-high")`. The adapter does not look for a `cdk_nag` import string, because a comment containing that string would hide the gap. A synth whose `cdk` binary is absent raises `ToolGap("missing", "security.workflow-infra-high")`. Card C3's repository check is not written here. Synthesizing executes the application. This card does not add a sandbox beyond the allow-listed environment. Rejected: skipping synth and reading source with a regex. The issue says the findings sit on the synthesized templates. Rejected: passing the operator environment through. A CDK application could read cloud and GitHub credentials.
- **KTD12. The drafts the operator reviews in card C7 are these, and they are data in the yaml.** ruff is started with `--select ALL`. The family map, confirmed against ruff 0.15.18's code prefixes, decides the level: F and B and S are error; C4, UP, SIM, and RUF are warning; E, W, N, and I are style. The longest matching prefix wins. A code whose prefix is not in that map is warning, so a family the draft does not name is fix later and is not dropped. actionlint has no levels. The kind strings are the ones actionlint 1.7.12's checks document prints in its example output (`docs/checks.md` at tag v1.7.12), not a single local run. A kind that means the workflow is invalid is error: `syntax-check`, `job-needs`, `events`, `workflow-call`, `glob`, `matrix`, `id`, `action`, `shell-name`, `env-var`, `runner-label`. A kind that means a permission, a credential, or an embedded script check is warning: `permissions`, `credentials`, `shellcheck`, `pyflakes`, `expression`, `if-cond`. A deprecation kind is style: `deprecated-commands`. Any kind not listed is warning. `action` also covers a deprecated action input in that document, so that input blocks until card C7 splits the kind. ShellCheck's `error`, `warning`, `info`, and `style` pass through, and cfn-lint's E, W, and I prefixes become error, warning, and info. Checkov's curated ids, dropped if checkov 3.3.25 has no such cloudformation check, are `CKV_AWS_62` and `CKV_AWS_63` (a wildcard Identity and Access Management action), `CKV_AWS_356` (a wildcard resource), and `CKV_AWS_20`, `CKV_AWS_53`, `CKV_AWS_54`, `CKV_AWS_55`, `CKV_AWS_56`, `CKV_AWS_57`, and `CKV_AWS_70` (public storage). Checkov is started with `--skip-download`, `--framework cloudformation`, and `-o json`, and without a platform key. Rejected: selecting only the drafted ruff families. Every other family would then be silent. Rejected: treating pycodestyle's `E` prefix as an error. The issue says that prefix is mostly style.
- **KTD13. Formatters are `mode: fix` and the review runner never starts them.** `ruff-format` uses tool `ruff`. `shfmt` uses tool `shfmt`. The runner already skips `mode: fix` before the version probe and before invoke. Card C11 is what runs them in the build loop. Rejected: emitting a note per formatted file. The lens table says review never sees formatting.
- **KTD14. The pins are exact, and the three Python toolchain pins stay the numbers the context library already publishes.** Read on 2026-10-07 from `infiquetra-context-library` `docs/repositories/python-toolchain.md`: ruff `0.15.18`, mypy `2.1.0`, bandit `1.9.4`. PyPI's newer ruff `0.16.10` and mypy `2.4.0` are not the pin. The other pins are the current releases checked the same day: coverage `7.16.2`, cosmic-ray `8.7.0`, pytest-randomly `5.0.0`, pytest-socket `0.8.1`, vulture `2.16`, import-linter `2.15`, pip-audit `2.10.1`, checkov `3.3.25`, cfn-lint `1.57.2`, ShellCheck `0.11.0`, shfmt `3.14.1`, actionlint `1.7.12`, zizmor `1.30.1`, lychee `0.24.2`, markdownlint-cli2 `0.23.3`, cspell `10.3.6`, cdk-nag `3.0.2`. `default_version` is the string the runner's version regex extracts, with no leading `v`. import-linter 2.15's version option prints `import-linter 2.15`, so the extracted token is `2.15` and the pin stays `2.15`. If a binary prints a longer triplet than the package label, the yaml uses the extracted string. Rejected: floating to whatever is newest on PyPI for ruff and mypy. Those two numbers are the pins this list is taking over, and a bump has not been through the corpus.
- **KTD15. pip-audit's hit carries advisory ids and no score.** `advisory_ids` includes the vulnerability id and its aliases. `score` is none. `row` is `security.dependency-high`. `review_formula.merge_advisories` then keeps osv-scanner's hit when the id sets intersect, including a medium score, so the result is one fix-later finding. The tests feed both fixtures through one `run`. pip-audit and lychee have no live test, because they use the network. Rejected: copying a Common Vulnerability Scoring System number out of pip-audit's description. The issue says the output has no score.
- **KTD16. This card appends its modules to the fingerprint tuple and does not create the calibration file.** The five paths are `plugins/saga/scripts/review_adapters_python.py`, `plugins/saga/scripts/review_adapters_infrastructure.py`, `plugins/saga/scripts/review_adapters_shell.py`, `plugins/saga/scripts/review_adapters_workflows.py`, and `plugins/saga/scripts/review_adapters_markdown.py`. `review-tools.yaml` is already in the tuple. If `review_calibration.py` exists at implementation time, its component list gains these paths in the same commit. ## High-Level Technical Design

The new modules export `ADAPTERS`, built from the rows in `plugins/saga/references/review-tools.yaml` whose ids they own. The every-language builder keeps skipping ids it does not know. A run that passes no adapter list gets both sets.

```mermaid
flowchart LR
    Y[review-tools.yaml] --> M[five adapter modules]
    M --> D[default_adapters]
    D --> R[review_tools.run]
    R --> F[line filter or base against head]
    F --> O[findings.json and outcomes.json]
```

`invoke` returns an argument vector and does not run it. `parse` reads that tool's machine-readable output. The runner supplies the process, the timeout, and `shell=False`. Plugins that are not binaries (`pytest-randomly`, `pytest-socket`, `cdk-nag`) set `version_argv` to a `python3 -c` probe of `importlib.metadata.version`. Their `tool` string is the adapter id, so a baseline command that merely contains `pytest` or `python3` is not classified as those rows.

The catalogue matcher in `plugins/saga/scripts/build_loop.py` matches the binary name only. After this card, `uv run ruff check .` and `uv run ruff format --check .` both answer `ruff-format,ruff-lint`. `uv run mypy …` answers `mypy`. `uv run pytest …` stays repository-specific. Green is still the profile's `mechanical_tool_baseline`. The dry-run fixture whose only command is `uv run ruff check .` no longer prints "no catalogue check", and `bandit` appears in the uncovered list because that fixture does not run bandit.

## Implementation Units

### U1. Python static adapters

Bandit, pip-audit, mypy, ruff lint, vulture, and import-linter, plus the runner fields they share with the later units.

**Goal:** Those six tools emit the rows in KTD4, mypy keeps an error in an untouched file, and the runner can carry a base commit and a test command.

**Requirements:** R1, R2, R3 for pip-audit, R4 for ruff's families.

**Dependencies:** none.

**Files:** `plugins/saga/scripts/review_tools.py` (`ScanContext.base`, `ScanContext.test_command`, `Adapter.version_argv`, `Adapter.narrow_env`, `_run_adapter` setting those two context fields, `_read_version` honoring `version_argv`, `_execute` applying the relocated allow-list when `narrow_env` is true, the silence needles in `_COMMENT_MARKERS`, and a `ToolGap` from `parse` recorded the same way as one from `invoke`); `plugins/saga/scripts/review_adapters_python.py` (create); `plugins/saga/references/review-tools.yaml` (these rows); `plugins/saga/tests/test_review_adapters_python.py` (create); `plugins/saga/tests/fixtures/review_tools/` (recorded output, inert values); `plugins/saga/tests/test_build_loop.py` (the catalogue assertions for the binaries this unit adds).

**Approach:** Add the fields from KTD1 with defaults so existing constructors keep working. `_run_adapter` sets `base` from the resolved base commit and `test_command` from the profile the runner already loaded from the base blob. `_read_version` uses `version_argv` when it is non-empty. `_execute` uses the relocated allow-list only when `narrow_env` is true. Do not concatenate the new modules into `default_adapters()` until U5, so this unit's tests inject the adapters. The python module's `_build` reads `load_tool_list()` and builds only its ids. mypy sets `type_checker=True`. Its argument vector passes `--config-file` pointing at the base commit's mypy configuration, written under the runner home. When the base commit has none, that file is a minimal config and the vector still does not pass `--strict`. The parser reads `path:line:col: error|note|warning: message [code]`. A note is level `style`, because `note` is not a tool level. The anchor includes the message, so two errors in one untouched file stay distinct. pip-audit follows KTD15 and KTD5, including the `scanner-false-positive` rerun. import-linter passes `--config` pointing at the base commit's contract, written under the runner home. No contract at base returns no argument vector, not a degraded input. Bandit uses `--ignore-nosec` and a config the adapter writes under that home with an empty skip list. ruff lint uses `--isolated`, `--ignore-noqa`, and `--select ALL`. The family map decides the level, and an unknown prefix is warning. vulture's hit sets the dead-code row directly. Each tool's test plants a suppressing config in the scanned tree and still expects the fixture finding. A live check for bandit, mypy, ruff, vulture, and import-linter skips unless the probed version equals the pin. pip-audit has no live check.

**Patterns to follow:** `plugins/saga/scripts/review_adapters_all_languages.py` for building an `Adapter` from a yaml row, and `plugins/saga/tests/test_review_adapters_all_languages.py` for the injected runner, the socket guard, and the builder-excuse rerun.

**Test scenarios:**

- Happy path, bandit: a HIGH result on a changed line becomes `security.scanner-high` and severity blocks. The same finding with a `scanner-false-positive` reason becomes a note. A MEDIUM result and a LOW result are `security.scanner-medium-low` and fix later. A HIGH result on an unchanged line is absent.
- Happy path, pip-audit: an unscored `PYSEC-EXAMPLE` blocks. The same finding with a `scanner-false-positive` reason becomes a note. The same id in an osv-scanner fixture with a medium score, fed through the same `run`, is one finding and fix later. An advisory present in the base fixture and the head fixture is absent.
- Happy path, mypy: base emits `untouched.py:1: error: bad [assignment]`. Head emits that line plus `untouched.py:2: error: worse [assignment]`. The kept finding is the second, `correctness.type-error`, severity blocks, and `untouched.py` is not in the diff. The anchor contains the message. A mypy note is `correctness.tool-style`. The argument vector's `--config-file` is outside the worktree. A head `pyproject.toml` that silences the error does not hide it.
- Happy path, ruff: `F401` is error and blocks; `E501` is style and a note; `UP032` is warning and fix later; `ZZZ999` is warning. The argument vector contains `--isolated`, `--ignore-noqa`, and `--select ALL`. A worktree `ruff.toml` that ignores `F401` does not hide the finding.
- Happy path, vulture: a dead function on a changed line is the complexity row and a note. import-linter: a broken contract new at head is the structural row and blocks. The same break at base and head is absent. No contract at base does not degrade.
- Secret: bandit's `code` is `EXAMPLE_NOT_A_SECRET = 1`. That token is absent from `findings.json`, `measurements.json`, `degraded.json`, and `outcomes.json`.
- Failure: a missing `bandit` binary is a degraded input, reason `missing`, and exit 0. A non-JSON payload is reason `unparseable`.
- Isolation: bandit, mypy, ruff, vulture, and import-linter each report the fixture finding while a suppressing config sits in the scanned tree.
- No network: the socket guard from the every-language adapter tests, and no test invokes pip-audit except through the injected runner. Live checks skip unless the installed version equals the pin, and they pass no network flag the tool would use to fetch rules.

**Verification:** the mypy untouched-file finding blocks, the pip-audit merge is one fix-later finding, and `test_the_python_baseline_runs_and_records_each_result_with_its_catalogue_check` names `ruff-lint` and `mypy` instead of an empty catalogue check for those commands.

**Functional checks:**

## Scope Boundaries

This card adds the adapters, their rows, their fixtures, and the write-up. It does not install tools, write a repository's pins, or teach the build loop to call the runner.

**Deferred to follow-up work**

- Card C3 installs these tools, records their pins in the profile, records the coverage command from KTD9, and names an application that does not apply cdk-nag.
- Card C7 is the operator's review of the drafts in KTD12. The drafts ship as data so that review has something to accept or replace.
- Card C11 calls the runner from the build loop and is what actually runs ruff format and shfmt.
- Card C4c is TypeScript, Dart, Rust, and Swift. Card C5 is saga's own Semgrep rules. Card C2 creates the calibration file if it has not landed, and includes the tuple from KTD16.
- The context-library change that replaces the ruff, mypy, and bandit pins with a link to this list is program item X2.
- A sandbox around `cdk synth` beyond the allow-list in KTD11. Synthesizing still executes the application. It does not receive the operator's credential variables or home directory. It can still do what the binary on `PATH` and the network allow.
- Narrowing the environment of adapters that do not execute the commit under review. KTD8 and KTD11 narrow the three test commands, cdk-nag, checkov-cdk, and zizmor. The other adapters stay on the operator environment.

**Non-goals**

- Editing the runner's line filter, base-against-head comparison, coverage parser, mutation cap, or record builder.
- Grades, and which lens may block. Those stay card C1 and card C2. With no calibration answer, a blocking row is reported and does not stop a merge, which is already how the formula behaves.
- Skipping a tool when the diff has no file of its language. The runner does not do that today, and a type checker must still see an untouched file.

## Risks & Dependencies

| Risk | Mitigation |
|---|---|
| A drafted family or kind blocks a style finding | The mapping is data in the yaml and the guide. Unknown ruff prefixes and unknown actionlint kinds are warning, which is fix later. Card C7 reviews the draft before a lens may block |
| A head settings file suppresses a finding | KTD5 points every tool at an isolated config, a home-directory config, or a copy, and disables or strips inline silences. One test per family plants the suppressing config in the scanned tree and asserts the finding is still reported |
| `cdk synth` executes the commit | KTD11 runs it with the relocated allow-list and no credential flag. That is not a sandbox. Tests feed recorded templates and do not synth a real application |
| Adding `tool: ruff` turns today's baseline red | The profile commands still decide green. U1 and U5 update the catalogue assertions. A missing review tool is a degraded input, exit 0 |
| The version regex extracts `2.15.0` while the package label is `2.15` | The yaml stores the extracted string. The version test checks the shape, not a fresh download |
| Card C2 lands during this work and grows its own path list | The fingerprint test fails unless that file contains the five paths |
| Two Checkov rows share one binary, so a baseline `checkov` command covers both | Same rule as the two Semgrep rows. The issue's comparison difference is on the adapter, not on the catalogue matcher |

Depends on card C4a, which has landed, including issue #191. Does not depend on card C2 or card C3.

## Alternatives Considered

- **Create `review_calibration.py` in this card.** Rejected. The issue says to edit it if it has landed, and otherwise to let card C2 add the paths. The tuple issue #151 published is that hand-off.
- **One Checkov adapter that sets `whole_project` only for synth hits.** Rejected. One adapter has one comparison, so it cannot scan synthesized templates base against head and also keep hand-written templates on the changed-line filter. `filter_to_change` keeps a hit that sets `whole_project`. Two ids are what give the two scan modes.
- **Pass the operator's GitHub token to zizmor so the online audits run.** Rejected. The row the issue names, an unpinned action, is an offline finding. A token in a scan of an untrusted workflow is the larger risk.
- **Pin ruff `0.16.10` and mypy `2.4.0` because those were current on PyPI.** Rejected. The context library's published pins are the numbers this list is replacing as the authority. A bump is a later change to the yaml, after the corpus.
