# saga cosmic-ray adapter reports survivors and unfinished runs (issue #227)

## Summary

Fix saga's Python mutation adapter for cosmic-ray 8.7.0: write the distributor table the tool requires, parse its array-form dump, report every errored or unrun mutant and every failing baseline as unfinished, and resolve both bare-`python` heads to the review interpreter so mutant workers run with pytest available.

---

## Problem Frame

Issue #227 is a defect card in the saga review redesign program (parent issue #147). Saga's cosmic-ray adapter feeds the testing lens, which the corpus calibration measures; it currently reports zero surviving mutants on code whose tests assert nothing, and it reports broken runs as clean. It blocks the first full corpus run.

The card's diagnosis was verified empirically on a machine with the pinned cosmic-ray 8.7.0 before this plan was written, with two refinements. A config without the distributor table makes `cosmic-ray exec` exit 78 with `ConfigKeyError('distributor')`. With `name = "local"` added, init and exec exit 0 and the dump holds 11 lines, every one a JSON array `[work_item, result]` with the outcome at `result.test_outcome`, the worker state at `result.worker_outcome`, the path at `work_item.mutations[0].module_path`, and the position at `work_item.mutations[0].start_pos` (`[2, 16]`, line 2). Refinement one: the path key is `module_path` on the mutation record; the work item carries no `module` key. The installed 8.7.0 source confirms the schema: each dump line is a two-element list, the result may be null for pending work, `worker_outcome` is one of normal, exception, abnormal, no-test, or skipped, and `test_outcome` is survived, killed, incompetent, or null.

Refinement two is about failure modes. A suite that fails on unmutated code makes every mutant `killed`; a test command whose binary is missing makes every mutant `incompetent`; both runs exit 0 and read as clean under the current wrapper. So the fix must treat `incompetent` as unfinished and must run a baseline, not only check the exec exit code.

The card's unverified point is settled: inside `uv run --with cosmic-ray==8.7.0`, checked with the offline flag so nothing was downloaded, `python` resolves to the temporary environment's interpreter, which has no pytest. Production mutant workers therefore run the repository's test command without pytest today. The fix resolves the interpreter absolutely instead of trusting PATH.

## Requirements

Requirements are grouped by concern. R-IDs run continuously. AC-n is the nth checkbox under the issue's Acceptance criteria.

**Config and interpreter**

- R1. The generated `cosmic-ray.toml` carries a `[cosmic-ray.distributor]` table with `name = "local"` and a per-mutant `timeout` of 300 seconds; `cosmic-ray init` plus `cosmic-ray exec` on a generated config both exit 0 (AC-1).
- R2. The adapter invokes the wrapper under the current interpreter, never a bare `python` head (AC-1).
- R3. The test command written into the config resolves a leading `python` or `python3` token to the absolute current interpreter. Any other head, and any absolute head, passes through unchanged (AC-3).
- R9. The `pytest-randomly` and `pytest-socket` adapter commands resolve a leading `python` or `python3` token to the absolute current interpreter, the same rewrite as R3 (AC-3).

**Results**

- R4. A recorded 8.7.0 dump yields one `surviving-mutant` finding per survived mutant at the mutation's module path and start line. Killed mutants yield no finding (AC-1).
- R5. Any errored or unrun mutant marks the run unfinished: a worker outcome other than normal, an `incompetent` or null test outcome, a null result, or a dump line that is neither blank nor a two-element array. Survivors found alongside such mutants are still reported (AC-2).
- R6. The wrapper runs the test command once on the unmutated code first. A failing or timed-out baseline marks the run unfinished and skips the mutation run (AC-2).

**Tests and documents**

- R7. The live survivor test runs under the current interpreter and passes where the pin is installed. It skips with a stated reason when the pin or a usable Python is missing. An offline test fails if the workers would resolve to an interpreter without pytest (AC-1, AC-3).
- R8. The changelog gains a Fixed entry under Unreleased with no version bump, and the engineering journal gains the lesson with evidence, mechanism, and rule.

## Key Technical Decisions

Each entry is the decision, then why, including the rejected alternative.

- **KTD1. The generated config appends `[cosmic-ray.distributor]` with `name = "local"`, after the last `[cosmic-ray]` key.** Version 8.7.0 requires the key; without it exec exits 78, verified. `local` runs the workers on this machine; the tool lists only `local` and `http`, and `http` needs a remote endpoint this repository does not run, so it is rejected. Appending after the last key matters because a table header mid-file would orphan the keys below it under the wrong table.

- **KTD2. The wrapper parses each dump line as `[work_item, result]`, reads the survivor position from `mutations[0].module_path` and `start_pos[0]`, and drops the `{`-object branch.** The array shape, the lowercase outcomes, and the `module_path` key were verified against a live 8.7.0 dump and the installed source; the work item has no `module` key, which refines the card. Both `survived` and `SURVIVED` keep matching, the cheapest tolerance. Keeping the `{` branch was rejected: against a fixed pin it is dead code no recorded dump can exercise.

- **KTD3. Unknown results fail closed to unfinished, and survivors are still reported.** Any worker outcome other than normal, any `incompetent` or null test outcome, any null result, and any non-blank unparseable line marks the run unfinished; a work item with no mutations does the same. Skipping unknown lines was rejected because that is the current bug. Dropping survivors on an unfinished run was rejected because the testing lens already degrades them to fix-later under reason `cap`, which the existing unfinished test pins.

- **KTD4. The baseline runs in the wrapper, first, with the same command string the workers get, bounded by a 300-second budget the adapter passes as a wrapper argument; a red baseline skips the mutation run, and the config's per-mutant timeout is the same 300 seconds.** Only the wrapper shares the workers' environment: the narrowed allow-list environment plus the temporary uv environment on PATH. A baseline beside the adapter was rejected because it would pass while the workers fail. Running the mutants anyway on a red baseline was rejected because it burns the mutation budget for zero signal. The shared budget sits inside the row's 900-second adapter timeout; a suite slower than the budget fails the baseline instead of timing out per mutant into all-killed, which reads as clean. A mutant-introduced hang still classifies as killed, the upstream semantic for timeouts, which the dump cannot distinguish.

- **KTD5. The adapter invokes the wrapper with the current interpreter instead of the literal `python`.** The wrapper needs only the standard library, so any interpreter runs it, and an absolute path is immune both to uv shadowing and to machines with no `python` on PATH. `python3` was rejected because it still resolves through PATH and the card requires the current interpreter or a stated skip.

- **KTD6. A leading `python` or `python3` token in the profile test command is rewritten to the absolute current interpreter when the config is written; every other head passes through.** Verified: the temporary uv environment shadows `python` with an interpreter that has no pytest, and a missing `python` turns every mutant `incompetent`, which reads as clean. The review interpreter is the one that already runs repository tests elsewhere in saga. Adding pytest to the `--with` list was rejected because the temporary environment would still lack the repository's other test dependencies, and it touches the pin surface the card freezes. Rewriting non-Python heads was rejected because the adapter cannot know what `make` or `tox` needs.

- **KTD7. The dump fixture is recorded 8.7.0 output, trimmed to one survived and one killed line with the opaque `output` and `diff` values shortened, plus schema-faithful synthesized error and pending lines; a pin-gated live test re-records and re-parses as a cross-check.** Recorded lines pin the real schema; committing full eleven-line blobs was rejected as noise, and hand-writing every line was rejected because it drifts from the tool. The live cross-check keeps the fixture honest when the pin is present and skips with a stated reason when it is not.

- **KTD8. The `pytest-randomly` and `pytest-socket` adapters get the same head rewrite in `_pytest_argv`.** They head their commands with the profile's bare `python` under the same temporary uv environment, so they share the pytest-less failure exactly; the coordinator ruled them in scope for this card. Leaving them was rejected because the same false-clean would survive next door.

## Risks & Dependencies

Four risks, each with its mitigation.

- **The dump schema follows the pin.** If a later card moves the pin, the array shape or the outcome vocabulary may move with it. The fixture is recorded output and the live cross-check re-records on every pin-bearing run, so drift fails loudly.
- **The baseline runs the suite twice.** On a large repository the extra run costs minutes. The mutation row already allows 900 seconds and the program caps mutation work per review at 15 minutes; one bounded baseline fits inside both, and a red baseline saves the whole mutation run.
- **uv's PATH shadowing is version-dependent behavior.** A future uv could resolve `python` differently. The absolute interpreter removes the dependence instead of tracking it, and the offline PATH test proves the independence rather than the current shadowing.
- **Live tests need the pin on the machine.** Every live test in this change skips with a stated reason when the pin, or a usable Python, is absent, following the existing pin-skip pattern. No test downloads a package.

---

## Alternatives Considered

Three rejected forks.

- **Install cosmic-ray as a real dependency instead of `uv run --with`.** Rejected: it widens the install surface the tool list deliberately avoids, and the temporary environment is fine once the interpreter is absolute.
- **Report `incompetent` mutants as findings instead of unfinished.** Rejected: an `incompetent` mutant says the harness is broken, not that the change is risky; the program records unfinished mutation work as degraded, which is the honest signal.
- **Teach the adapter the `http` distributor for faster runs.** Rejected: no remote endpoint exists in this environment, and speed is not the card's complaint.

---

## System-Wide Impact

Surviving-mutant findings will appear where the adapter previously reported none, so weak tests now block under the testing lens instead of passing silently; that is the card's intent. Broken runs move from silent clean to unfinished, which the runner already degrades to fix-later under reason `cap`. The calibration corpus measures the testing lens, so this change unblocks its first full run and changes what that run observes; no calibration file changes here. Timeouts, the mutation cap, and every other adapter are untouched.

### U1. Distributor table and the wrapper interpreter

The generated config satisfies cosmic-ray 8.7.0, and the wrapper runs under the current interpreter.

**Goal:** `_invoke_cosmic` writes a config the pinned tool accepts, and invokes the wrapper with an interpreter that exists.

**Requirements:** R1, R2.

**Dependencies:** none.

**Files:** `plugins/saga/scripts/review_adapters_python.py` (modify); `plugins/saga/tests/test_review_adapters_python.py` (modify).

**Approach:** Append the `[cosmic-ray.distributor]` table with `name = "local"` after the last `[cosmic-ray]` key and keep the git-filter table last; a table header placed above remaining keys would orphan them, so the writer appends tables only. Replace the literal `"python"` wrapper head in the adapter argv with the current interpreter, adding the import the module lacks. The temporary-environment prefix stays untouched.

**Patterns to follow:** `plugins/saga/scripts/review_adapters_python.py` `_invoke_cosmic` and `_toml_list` for config writing; `plugins/saga/scripts/review_tools.py` `_execute` for how a missing binary becomes reason `missing` instead of a finding.

**Test scenarios:**

- Happy path: a mocked run writes `cosmic-ray.toml`; the text contains the distributor table with `name = "local"`, the module list still holds every changed Python file, and the git-filter branch is unchanged.
- Live config: with the pin installed, `cosmic-ray init` and `cosmic-ray exec` on the written config both exit 0; without the pin the test skips with a stated reason.
- Wrapper head: the adapter argv after stripping the temporary-environment prefix starts with the current interpreter, and the stripped argv runs on a machine with no bare `python`.
- Shared budget: the written config sets `timeout = 300.0` and the wrapper argv carries the same budget as its timeout argument.
- Regression: the existing module-path and survivor-block tests still pass unchanged.
- Names: the new tests are `test_cosmic_ray_config_carries_the_distributor`, `test_cosmic_ray_exec_on_the_generated_config_exits_zero`, `test_cosmic_ray_wrapper_head_is_the_current_interpreter`, and `test_cosmic_ray_generated_config_shares_the_baseline_timeout`, so the functional check below matches exactly this unit.

**Verification:** the generated config carries the distributor table and the pinned tool runs it to exit 0. The wrapper head is absolute.

**Functional checks:**

### U2. Array-dump parsing

The wrapper reads the 8.7.0 dump and reports each survived mutant at the right file and line.

**Goal:** survivors from a recorded array dump become findings; killed mutants stay silent.

**Requirements:** R4.

**Dependencies:** U1.

**Files:** `plugins/saga/scripts/review_adapters_python.py` (modify); `plugins/saga/tests/test_review_adapters_python.py` (modify); `plugins/saga/tests/fixtures/cosmic-ray-8.7.0-dump.jsonl` (create).

**Approach:** Rewrite the wrapper's dump loop for two-element arrays: the survivor predicate reads `result.test_outcome` in either case, the path reads `mutations[0].module_path`, the line reads `start_pos[0]`. Blank lines are tolerated; the `{`-object branch is removed. Record the fixture by running the U1 live config against the trivial example repository, then trim to one survived and one killed line and shorten the opaque `output` and `diff` values, which the parser never reads. Drive the wrapper in tests with a stub `cosmic-ray` executable on PATH that prints the fixture for `dump` and exits 0 otherwise. The fixture repository stays the trivial example, so every value is inert.

**Patterns to follow:** the installed cosmic-ray 8.7.0 dump command for the line shape; the existing `_Calls` harness for mocked runner tests.

**Test scenarios:**

- Happy path: the recorded fixture through the stub yields one finding per survived line at the recorded module path and start line, and nothing for the killed line.
- First mutation wins: a work item with two mutations reports the first mutation's position.
- Missing position fails closed: a survived result whose work item has no mutations yields no finding and marks the run unfinished instead of crashing.
- Legacy shape fails closed: a `{`-object line marks the run unfinished, documenting that the old format is gone.
- Names: the new tests are `test_cosmic_ray_array_dump_yields_one_finding_per_survivor` and `test_cosmic_ray_array_dump_without_a_position_is_unfinished`, so the functional check below matches exactly this unit.

**Verification:** the recorded dump yields findings at the recorded positions, and position-less results never crash the wrapper.

**Functional checks:**

```functional-checks

  command: python3 -m pytest plugins/saga/tests/test_review_adapters_python.py -q --import-mode=importlib -k array_dump
```

### U3. Errors and the baseline mark the run unfinished

No errored, unrun, or never-baselined run reads as clean.

**Goal:** the wrapper reports unfinished for every outcome that is not a clean kill or survivor, and baselines the suite before mutating.

**Requirements:** R5, R6.

**Dependencies:** U2.

**Files:** `plugins/saga/scripts/review_adapters_python.py` (modify); `plugins/saga/tests/test_review_adapters_python.py` (modify).

**Approach:** Extend the U2 dump loop: a worker outcome other than `normal`, a test outcome of `incompetent` or null, a null result, and any non-blank line that is not a two-element array each set unfinished while survivors still accumulate. Run the baseline first in the wrapper with the same command string the config gives the workers, in the wrapper's working directory, which the adapter already relies on for relative module paths; a non-zero exit or a timeout sets unfinished and skips init, exec, and dump. A non-zero dump also sets unfinished. The adapter passes the 300-second budget as a wrapper argument; tests override it short so the timeout case runs fast.

**Patterns to follow:** `plugins/saga/scripts/review_adapters_python.py` `_parse_cosmic` for the survivors-plus-unfinished shape the runner degrades; the U2 stub-`cosmic-ray` harness, extended to record invocations and to fail the baseline command on demand.

**Test scenarios:**

- Happy path: a dump of only killed mutants stays finished with no findings.
- Error matrix: each of worker `exception`, `abnormal`, `no-test`, and `skipped`, test `incompetent`, a null result, a null test outcome, and a garbage line marks the run unfinished; a survivor on a neighboring line is still reported.
- Failing baseline: a baseline command that exits non-zero marks the run unfinished and the stub records no exec invocation.
- Passing baseline: a baseline that exits 0 lets init, exec, and dump run in order.
- Baseline timeout: a baseline that never returns marks the run unfinished within a short overridden bound, and the children it spawned die with it through a process-group kill.
- Failed dump: a non-zero dump marks the run unfinished.
- Regression: the existing unfinished-is-cap test still passes, pinning the degraded severity; it runs in the suite but is not part of the functional check below.
- Names: the new tests are `test_cosmic_ray_errored_mutant_marks_the_run_unfinished`, `test_cosmic_ray_failing_baseline_marks_the_run_unfinished`, `test_cosmic_ray_passing_baseline_runs_the_stages_in_order`, and `test_cosmic_ray_dump_failure_marks_the_run_unfinished`. The functional check below matches the first, second, and fourth; the third runs in the smoke.

**Verification:** every error shape and every red baseline yields unfinished, and a clean all-killed dump stays finished.

**Functional checks:**

```functional-checks
- name: cosmic-unfinished
  command: python3 -m pytest plugins/saga/tests/test_review_adapters_python.py -q --import-mode=importlib -k "marks_the_run_unfinished or failing_baseline"
  proves: [AC-2]
  runs: local
```

### U4. Test-command interpreter and the live test

Workers run the repository suite with pytest available, and the live test proves it without the network.

**Goal:** the config's test command cannot resolve to a pytest-less interpreter, and the live suite proves the whole path.

**Requirements:** R3, R7, R9.

**Dependencies:** U3.

**Files:** `plugins/saga/scripts/review_adapters_python.py` (modify); `plugins/saga/tests/test_review_adapters_python.py` (modify).

**Approach:** When writing the config, split the profile test command as today and rewrite a leading `python` or `python3` token to the absolute current interpreter, leaving flags, the `-p no:randomly` handling, and every other head untouched. Apply the same rewrite in `_pytest_argv` for the two sibling adapters. Point the live survivor test's profile command at the current interpreter and skip with a stated reason when pytest is not importable under it; the pin skip stays, and a small helper answers the usable-interpreter question so its branches are unit-testable. Prove AC-3 with an offline worker test: a `python` shim without pytest goes first on PATH, the adapter-written config runs through a stub distributor that classifies like the tool's own test runner, and the test fails unless a survivor is recorded, which only the absolute interpreter can produce. The coordinator's in-scope ruling extends this AC-3 guarantee to the sibling adapters, so their check cites AC-3 as well.

**Patterns to follow:** `plugins/saga/scripts/builder_record.py` for running repository pytest under the current interpreter; `plugins/saga/scripts/review_tools.py` `_rewrite_command` as the existing precedent for rewriting a test command before a subprocess receives it; the existing pin-skip pattern for live tests.

**Test scenarios:**

- Happy path: profile commands starting with `python` and with `python3` both write a test command headed by the absolute current interpreter.
- Pass-through: heads of `pytest`, `make`, and an absolute path reach the config unchanged, with flags intact.
- Worker proof: with a pytest-less `python` shim first on PATH, the stub distributor still records a survivor from the adapter-written config.
- Sibling rewrite: the randomly and socket adapter commands head their pytest invocation with the absolute current interpreter for bare-`python` profile commands.
- Live survivor: the repaired live test passes where the pin is installed.
- Skips: without the pin the live tests skip naming the pin; with the pin but no pytest under the current interpreter they skip naming the interpreter. The helper returns the interpreter on this machine and none with pytest hidden.
- No network: the new tests run under the existing socket guard and never invoke the temporary-environment prefix.
- Names: the new tests are `test_cosmic_ray_test_command_resolves_bare_python`, `test_cosmic_ray_worker_imports_pytest`, `test_cosmic_ray_usable_python_is_the_current_interpreter`, `test_cosmic_ray_usable_python_is_none_without_pytest`, `test_pytest_randomly_resolves_bare_python`, and `test_pytest_socket_resolves_bare_python`. The interpreter check below matches only the worker test; the sibling check matches the sibling tests; the live check matches the repaired live test.

**Verification:** the written test command is absolute, a worker proves pytest is importable with a hostile `python` on PATH, and every live test either passes or skips with its reason stated.

**Functional checks:**
