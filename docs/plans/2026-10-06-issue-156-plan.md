# The Jev sweep says where to look in a change (issue #156)

## Summary

Saga cuts a change into small pieces, and fleet-core's new `jev sweep` asks each piece the question bank through a swappable classifier. TypeSafe's Jev is the classifier today. The result is a where-to-look list of at most 30 items, highest probability first, costing at most $1 a review.

---

## Problem Frame

This is card C6 of the saga review redesign (parent issue #147). Issue #156 is requirements-ready. The build loop (card C11) and the review command (card C10a) will both call this sweep later. Nothing calls it in this card.

Today `jev` asks one fixed question set about one whole state. Its subcommands are `ask`, `eval`, and one per registered verb (`plugins/fleet-core/scripts/jev.py`, `build_parser`). The `lenses` verb asks five yes/no questions of a whole diff. Nothing splits a change into pieces.

The TypeSafe client redacts state and questions before any transport sees them, caches an answer by the prepared state, the questions and the requested model, and returns token counts, latency and the resolved model. It returns no price (`AskResult` in `plugins/fleet-core/scripts/fleet_commons/typesafe_client.py`). The state budget is 32,000 tokens for the state plus the longest question, and 64,000 for the state plus every question (`STATE_TOKEN_BUDGET`, `TOTAL_TOKEN_BUDGET`).

`plugins/fleet-core/references/typesafe.md` lets diffs leave the machine. It does not let a whole function or a whole file leave. House rule 5 batches every question about one state into one request. House rule 7 logs every verdict with the resolved model version. House rule 8 fails open and says which side. House rule 9 rules out adversarial screening.

Saga receives fleet-core only as bundled copies of the modules its `fleet-bundle.json` declares, loaded through `plugins/saga/scripts/bundled_fleet.py`. The price table lists Claude models only. C4a's diff reader (`plugins/saga/scripts/review_diff.py`) reports added and modified lines. It does not report functions. C1's where-to-look record requires an `answer`, and card C8 is what writes that answer. C2's calibration file is not on this branch: `plugins/saga/scripts/review_calibration.py` is absent.

## Requirements

Requirements are grouped by concern. R-IDs run continuously. Each one traces to the issue's acceptance criteria, numbered AC-1 through AC-11 in the order the issue lists them.

**The command**

- R1. `python3 plugins/fleet-core/scripts/jev.py sweep --help` exits 0, and the help names the bank, the pieces, the thresholds, the rate, the repository and the head commit. AC-1.

**Pieces**

- R2. A changed Python function is one piece. The text is the function at the head commit, including its decorators. A rename that edits nothing produces no piece. AC-2.
- R3. For any other language, Universal Ctags supplies the function span. When that parser is missing, or it finds no span, the piece is the changed block plus 20 lines on each side, clipped to the file, and the piece is marked degraded. AC-2.
- R4. `plugins/saga/references/review-tools.yaml` carries Universal Ctags as a row with the same fields the other rows carry, so setup can check and install it the way it checks the others. The review runner does not execute that row. AC-3.

**Classification**

- R5. The list holds at most 30 items, highest probability first. Anything the cap cuts is listed as degraded and is not an item. When no threshold is set, the 30 are the most likely items, with no minimum probability. AC-4.
- R6. A question that has a threshold fires only when its probability is greater than or equal to that threshold. AC-4.
- R7. A multiple-choice question is asked in two option orders, both entries in the one request for that piece, and the two probability maps are averaged by option. A yes/no question is asked once. AC-5.
- R8. `plugins/saga/references/model-prices.yaml` carries one TypeSafe row with its source and its own date. The sweep prices the client's `input_tokens` and `output_tokens` at that row's rate and does not send another request once the spend has reached $1. What was not asked is listed as degraded. AC-6.
- R9. Every verdict-log line carries the resolved model version. Every item carries the same version on `classifier.model`. AC-7.
- R10. A secret planted in a piece never appears in the request body. The only way code leaves the process is `typesafe_client.ask`, which redacts first. The assertion lives in `plugins/fleet-core/tests/test_jev_sweep.py`. AC-8.

**Policy, bundle, fingerprint**

- R11. `typesafe.md` allows the three piece kinds after redaction, records that the sweep never blocks or clears a change and so is not adversarial screening, and states the 30-item cap, the $1 cap and the fail-open side. `docs/engineering-journal/DECISIONS.md` records the wider data rule. AC-9.
- R12. `python3 scripts/bundle_fleet_module.py --check` passes with `jev_sweep` declared in saga's bundle. The bundled file is produced by the bundler. AC-10.
- R13. The sweep's paths are named in a tuple this card owns. When C2's fingerprinted component list already exists, those paths are in that list too. AC-11.

## Key Technical Decisions

- KTD1. Two halves, and the names the card proposed. `plugins/fleet-core/scripts/fleet_commons/jev_sweep.py` classifies pieces it is given and reads no YAML and no saga file. `plugins/saga/scripts/sweep_pieces.py` cuts the pieces. `jev sweep` is its own subcommand, beside `ask` and `eval`, because a registered verb asks one fixed question set about one `--state`. Rejected: parsing non-Python in fleet-core, which would leave the standard library, and classifying inside saga, which would fork the client.
- KTD2. The external parser is Universal Ctags, binary `ctags`. One row can describe it, and `--output-format=json --fields=+ne` prints a start line and an end line. The invocation is an argument vector with `--options=NONE`, so a `.ctags` in the change under review cannot change the parse. Python uses `ast` and never this binary. A missing binary, a binary whose `--version` text does not contain `Universal Ctags`, a tag with no integer `end`, or no tag covering the changed line: that file falls back under R3. Rejected: the `tree-sitter` command, which needs a grammar and a query per language and prints prose, and ast-grep, which needs a pattern per language.
- KTD3. The bank is JSON (JavaScript Object Notation), schema `question_bank.v1`. Each question has `id`, `lens`, `kind` (`yes-no` or `choice`), `options` (each `id` and `definition`), `examples`, `not_for`, `when` and `piece`. `when` may list `languages` and `paths`. The piece's language must be in `languages` when that list is present, and its path must match one path pattern when that list is present. An absent `when` matches every piece. `piece` is `function`, `block` or `file`. A `yes-no` question's options are `yes` then `no`. A `choice` question has at least two options, and the first option is the one whose probability fires. C7 writes the banks. This card defines the format and accepts it as input.
- KTD4. A small whole file is at most 400 lines (`SMALL_FILE_MAX_LINES`). The client's estimate is three characters a token. Four hundred lines at 120 characters is about 16,000 tokens, half of the 32,000-token state budget, so the questions still fit beside the file. A longer file is not sent. The question that asked for it is listed degraded with reason `file-too-large`. The block window is exactly 20 lines before the first changed line of a contiguous run and 20 after the last, clipped to the file. Overlapping windows in one file merge into one piece.
- KTD5. Saga reads thresholds. Fleet-core receives them. When `plugins/saga/references/review-calibration.json` is absent, or its `thresholds` list is empty, saga passes `{}` and R5's most-likely rule applies. A row is `question`, `threshold` and `piece_size`, the shape C2's card assigns this file. `threshold` is the number R6 compares. `piece_size`, when present, is the maximum line count of that question's piece, and it replaces the bank's default for that question only. A file that exists and is not valid JSON raises. An empty list and a corrupt file are different events, and a corrupt file must not silently widen the list to the 30 most likely.
- KTD6. An item is one location and one lens. Its probability, for ordering, is the highest firing probability among its questions. Ties break by path, then start line, then lens. The 31st item is not returned as an item. It is a degraded entry with reason `cap`. Spend is computed in `Decimal` from the client's usage: `input_tokens` at the row's `uncached_input`, `output_tokens` at `output`. The three cache categories are zero because this client does not report cache tokens. Once the running spend is at least $1, the sweep sends nothing further. The request that crossed the cap is kept, because its tokens were not known until it returned.
- KTD7. One request per piece. Every question whose `when` and `piece` match that piece goes in that request. A `choice` question contributes two entries, the bank's option order and the reversed order. A `yes-no` question contributes one `noul` entry. The sweep calls `prepare_state` first and sends only when that call reports no truncation. When the piece and its questions do not fit, the sweep splits that piece by lens and tries again. A lens that still does not fit is not sent, and those questions are degraded with reason `budget`. An abridged piece would hide the code the question is about, so the truncation ladder is not a send path.
- KTD8. The TypeSafe row is model id `jev-1.13.0`, vendor `typesafe`, aliases `jev-latest` and `jev`. Its five rates, in the categories `test_cost_report.py` requires, are `uncached_input` 0.042 and the other four 0. Output is free, which is a real zero. The row carries `source: https://docs.typesafe.ai/models` and `verified_on: 2026-10-07`. The table's own `verified_on` stays 2026-10-03, because that date is the Claude reading and this card does not re-read Claude's page. The loader learns the two optional per-row fields and ignores them on the Claude rows. Rejected: moving the table date without re-reading every rate, and a null rate, which would leave the sweep unpriced.
- KTD9. The sweep's item has every C1 field except `answer`. That is the shape in `plugins/saga/tests/fixtures/reviewer_answer/where-to-look.json`, and it is the object `reviewer_answer.to_records` copies before it sets `answer` and calls `validate`. The sweep does not invent a cleared reason or a finding id. The bundle test then sets `answer` to a cleared reason and asserts `review_records.validate` returns no problems. Rejected: writing a placeholder answer in the sweep, which would be a review result card C8 did not make.
- KTD10. A verdict's `decision_id` is `sweep:<repo>@<head>:<piece_id>:<question_id>`. One verdict per bank question, written after averaging, with the resolved model on the line. The two option orders are not two verdicts. A request that is not ok writes no verdict. No key, or any other classifier failure, returns no items, sets the sweep's failed mark, and lists one degraded entry (`no-key` or `classifier`). The review goes on. The open side is "nothing to look at", which can hide a real defect, and the record says so.
- KTD11. Probability comes from the answer's `probabilities` map when that map is present, averaged by option id across the two orders. When it is absent, the chosen option receives the answer's `confidence` and the other options share the remainder equally, and those two maps are averaged. A `yes-no` probability is the `noul` number. A `choice` probability is the averaged probability of the bank's first option. A question with no usable number does not fire and is degraded with reason `unreadable-answer`. The rest of that request still counts.
- KTD12. The fingerprint tuple is `SWEEP_COMPONENTS` in `sweep_pieces.py`: `plugins/fleet-core/scripts/fleet_commons/jev_sweep.py`, `plugins/saga/scripts/sweep_pieces.py`, and `plugins/saga/references/model-prices.yaml`. `review-tools.yaml` is already on C4a's `FINGERPRINT_COMPONENTS`, whose equality test names those five paths and no others, so this card does not edit that tuple. `review_calibration.py` is absent on this branch. This card does not create it. At implementation, if that module exists and defines `COMPONENTS`, append these three paths there and extend its equality test. If it does not, `SWEEP_COMPONENTS` is the list AC-11 names.
- KTD13. The fleet-core version stays `0.33.0`. Neither `plugin.json` is edited. A description change rewrites the marketplace and the Codex manifest, and a version change also rewrites every bundle stamp. No acceptance criterion asks for a new version. The Unreleased changelog is the record. `plugins/fleet-core/README.md` gains one sentence under "How a consumer gets a module": saga declares `jev_sweep`, and the bundler writes the copy.
- KTD14. The Ctags row's id is `universal-ctags`. `review_adapters_all_languages._build` skips an id that is not in its invoke map, so the review runner will not try to execute the parser as a scanner. The row's languages are `typescript`, `dart`, `rust`, `swift` and `shell`. `default_version` is `not-recorded`, the same value every other row in that file carries. `version_args` is `["--version"]`. The install text tells the operator to install Universal Ctags and says Exuberant Ctags does not qualify. Markdown, GitHub workflows and CloudFormation are not in that list. They use the R3 window and are marked degraded, because this parser is not a function parser for prose.
- KTD15. The Jev classifier passes `cache_dir` to `ask`. A second sweep with the same pieces, bank and cache directory does not call the transport. Tests pass a temporary directory. The default directory is the verdict log's directory, so a repeat on one machine hits the cache.

## High-Level Technical Design

Saga owns the diff. Fleet-core owns the questions. The rate and the thresholds cross the boundary as JSON, never as a file fleet-core opens.

| Step | Who | Input | Output |
| --- | --- | --- | --- |
| Read the diff | `review_diff.read` | repository, base, head | added and modified lines |
| Cut pieces | `sweep_pieces` | the diff, the head blob, the bank, the calibration rows | pieces: text, path, language, kind, location, degraded |
| Classify | `jev_sweep` | bank, pieces, threshold map, five-category rate | at most 30 items, plus a degraded list |
| Store the answer | card C8, later | the items | the same items with `answer` set |

A piece the sweep receives:

```json
{
  "id": "src/billing/charge.py:40-52",
  "path": "src/billing/charge.py",
  "language": "python",
  "kind": "function",
  "text": "def charge():\n    ...",
  "degraded": false,
  "location": {
    "scope": "lines",
    "file": "src/billing/charge.py",
    "lines": {"start": 40, "end": 52},
    "function": "charge",
    "anchor": "def charge():"
  }
}
```

The sweep returns `items`, `degraded` and `failed`. `items` is the pre-answer where-to-look list. `degraded` entries name a `reason` of `cap`, `budget`, `file-too-large`, `unreadable-answer`, `no-key` or `classifier`, plus the piece id and the question id when those exist. `failed` is true only for the sweep-level failure in KTD10.

The command, which `--help` must name:

```text
jev sweep --bank BANK --pieces PIECES --thresholds THRESHOLDS --rate RATE [--repo REPO] [--head HEAD]
```

Each of the four required flags is a JSON file. `--thresholds` may be `{}`. `--rate` is the five categories. `--repo` and `--head` are the two halves of the verdict id. The command prints the JSON result on standard output and exits 0, including when `failed` is true, because the review goes on. Malformed JSON or a missing file exits 2.

The classifier call is one batch per piece, not one call per question. The card's singular contract is the per-question input inside that batch: the question, its options and definitions, the piece, the path and the language. The result for the piece carries a probability per option, the classifier name, the resolved model, the token counts and the seconds.

## Implementation Units

### U1. The sweep classifies pieces it is given

Fleet-core gains the module that asks, caps, prices and logs. It does not read a diff.

**Goal:** `jev_sweep.sweep` turns a bank and a list of pieces into at most 30 pre-answer where-to-look items, using an injected classifier so the tests make no network call.

**Requirements:** R5, R6, R7, R8, R9, R10. KTD3, KTD6, KTD7, KTD9, KTD10, KTD11, KTD15.

**Dependencies:** none.

**Files:**

- `plugins/fleet-core/scripts/fleet_commons/jev_sweep.py` (new)
- `plugins/fleet-core/tests/test_jev_sweep.py` (new)
- `plugins/fleet-core/CHANGELOG.md`

**Approach:** The module loads `typesafe_client` and `jev_log` the way `jev.py` loads siblings, and it imports the standard library otherwise. Constants the policy document will quote live here: `ITEM_CAP` 30, `SPEND_CAP_USD` of `Decimal("1")`, `PIECE_KINDS` of `function`, `block`, `file`, `BLOCK_CONTEXT_LINES` 20 and `SMALL_FILE_MAX_LINES` 400. Saga reads the last two from this module through the bundle in U5, so the numbers have one home.

The Jev classifier builds the state as `path`, `language`, `piece` and `piece_kind`, builds the question map as KTD7 describes, and calls `prepare_state` before `ask`. It passes the temporary or default `cache_dir`. On `noul` it reads the probability. On `choice` it averages as KTD11 describes. The sweep then groups firing questions into items, sorts, cuts at 30, and prices usage with the rate it was given. It logs one verdict per firing question with `record_verdict`, using the decision id from KTD10. The logged answer is the averaged probabilities and the resolved model. A non-ok `AskResult` takes the KTD10 failure path and logs nothing.

A `yes-no` question whose first option is not `yes` is degraded as `unreadable-answer` and is not sent. Path patterns treat `*` as one path segment and `**` as any number of segments, implemented in this module with no third-party glob library.

**Patterns to follow:** `plugins/fleet-core/scripts/jev.py` for the sibling loader, `plugins/fleet-core/scripts/fleet_commons/jev_widen.py` for "a failed call writes no verdict", and `plugins/fleet-core/scripts/fleet_commons/typesafe_client.py` `ask` for the cache and usage fields.

**Test scenarios:**

- Happy path, `test_choice_is_asked_in_both_orders_and_averaged`: one piece, one `choice` question with options `leak` then `clean`. The fake transport records one request. That request holds two choice entries, and the second entry's criteria are the reverse of the first. Returned probabilities `{leak: 0.8, clean: 0.2}` and `{leak: 0.4, clean: 0.6}` become `{leak: 0.6, clean: 0.4}`. The item's question probability is 0.6.
- Happy path, `test_yes_no_is_asked_once`: one `yes-no` question produces one `noul` entry in that same single request. The item's probability is the returned `noul` value.
- Happy path, `test_a_threshold_keeps_a_question_below_it_off`: threshold 0.8 and probability 0.79 produce no item. Probability 0.8 produces the item.
- Happy path, `test_without_thresholds_the_thirty_most_likely_return`: no threshold map, 31 pieces with probabilities 0.01 through 0.31. The result has 30 items, the lowest probability is absent from `items`, and that missing piece is a degraded entry with reason `cap`.
- Happy path, `test_thirty_one_hits_return_thirty_highest_first`: the same shape with a threshold of 0. The items are ordered from 0.31 down, and the 0.01 piece is the degraded one.
- Happy path, `test_the_dollar_cap_stops_before_the_next_request`: rate `uncached_input` 1.0 and the other four 0, and a fake that reports one million `input_tokens` on the first request. The second piece is not sent. It is degraded with reason `budget`. The first request's item is kept.
- Happy path, `test_a_repeat_sweep_answers_from_the_cache`: the real `ask` with a fake transport and a temporary `cache_dir`. The second call does not invoke the transport, and the items match.
- Happy path, `test_a_switch_keeps_a_question_off_a_piece_it_does_not_match`: `when.languages` of `["rust"]` against a Python piece sends no question and returns no item.
- Error path, `test_a_failing_classifier_returns_no_items`: the fake returns a non-ok status. `items` is empty, `failed` is true, the degraded reason is `classifier`, and the verdict log has no new line.
- Error path, `test_a_missing_key_is_its_own_reason`: the fake returns the client's no-key note (`TYPESAFE_API_KEY is not set in the environment; no request was attempted`). The reason is `no-key`, and still no items.
- Error path, `test_a_secret_in_a_piece_never_reaches_the_request_body`: the piece text contains `api_key = "example-secret-value"` and a synthetic token of `ghp_` plus 36 `X` characters. The captured body contains `[REDACTED]` and contains neither secret. The test uses the real `prepare_state` path.
- Edge case, `test_each_item_and_each_verdict_carries_the_resolved_model`: the fake resolves `jev-1.13.0`. Every item's `classifier.model` is that string, and every verdict line's `resolved_model` is that string. `classifier.name` is `jev`.

### U3. Saga cuts one piece per changed function

The diff reader stays the source of changed lines. This unit adds the function cut and the parser row.

**Goal:** `sweep_pieces.pieces` returns one piece per changed Python function, uses an injected parser for other languages, and falls back to the 20-line window when that parser is absent.

**Requirements:** R2, R3, R4. KTD2, KTD4, KTD5, KTD14.

**Dependencies:** U1, for the constant values. The tests assert the numbers directly, so this unit does not import the bundle.

**Files:**

- `plugins/saga/scripts/sweep_pieces.py` (new)
- `plugins/saga/tests/test_sweep_pieces.py` (new)
- `plugins/saga/references/review-tools.yaml`
- `plugins/saga/CHANGELOG.md`

**Approach:** Call `review_diff.read` for the lines and `review_tools.language_for` for the language. Read each file's text with `git show <head>:<path>` as an argument vector, never from the worktree. Python goes through `ast`. A changed line belongs to the innermost `FunctionDef` or `AsyncFunctionDef` that contains it. The span starts at the first decorator when the function has one. A changed line outside every function becomes a window piece with `function` null and `degraded` false, because the parser ran. `ast.parse` failing is the R3 fallback with `degraded` true.

For a language on the Ctags row, call the injected parser. The real parser runs `ctags --options=NONE --output-format=json --fields=+ne -o - -- <tempfile>`, writes the head blob to a temporary file outside the repository, and keeps a tag whose `kind` is `function`, `method` or `member` and whose `end` is an integer. The innermost covering span wins. Tests pass a fake parser and never require the binary.

Build a `block` piece only when some question asks for `block`, and a `file` piece only when some question asks for `file` and the file is at most 400 lines. A function question still matches a fallback window, and that piece's `kind` stays `function` so the question is asked. The window is marked `degraded`.

Read calibration as KTD5 describes. Do not import `review_calibration`. A `piece_size` on a row clips that question's piece to that many lines, centered on the changed lines, and the piece id gains the question id so two questions do not share a clip.

Add the `universal-ctags` row to `review-tools.yaml` with the fields KTD14 names. Do not add it to the invoke map in `review_adapters_all_languages.py`.

**Patterns to follow:** `plugins/saga/tests/test_review_diff.py` for the temporary git repository (`_init`, `_commit`), and `plugins/saga/scripts/review_tools.py` `language_for` for the suffix table. Do not copy that table.

**Test scenarios:**

- Happy path, `test_a_changed_python_function_is_one_piece`: a temporary repository, a function `charge` edited between base and head. One piece, `kind` `function`, `function` `charge`, text equal to the function at head, `degraded` false.
- Happy path, `test_a_fake_parser_makes_one_piece_for_another_language`: a changed `.rs` file and a fake parser that returns one span. One piece, `degraded` false, text equal to that span.
- Error path, `test_without_the_parser_the_piece_is_the_window_and_degraded`: the same `.rs` file, and the parser raises `FileNotFoundError`. The piece text is the changed line plus 20 lines on each side, clipped, and `degraded` is true.

## Scope Boundaries

**In scope.** The piece cutter, the parser row, the bank format, the sweep, the command, the TypeSafe price, the policy text, the decision journal, the saga bundle and the fingerprint tuple.

**Out of scope.** The banks' contents and the policy questions are card C7. Thresholds and piece sizes tuned on the corpus are the harness K3, stored in C2's file. Running the sweep from the build loop is card C11. Running it from the review command is card C10a. The reviewer's answer, including Jev's pick of a reproduced finding's consequence, is card C8. The where-to-look schema and its validator are card C1. Installing Ctags on a machine is card C3, from the row this card adds. A local classifier model is a later replacement, and it takes over only when it scores at least as well on the corpus. Posting verdicts to Langfuse is card C15.

**Deferred to follow-up work.** When C2's `review_calibration.py` lands second, that change appends `SWEEP_COMPONENTS` to `COMPONENTS`. This card appends them itself only when that file is already present. Re-reading the Claude rates and moving the table's single `verified_on` is a separate price-table change. A fleet-core version bump waits for a release, because it rewrites every bundle stamp.

## System-Wide Impact

The data rule gains three piece kinds. Code from a file the change touches may leave the machine after the client's redaction, and only through `typesafe_client.ask`. The sweep does not block, clear, or grade. A failure returns no items. Callers in later cards have to keep going when `failed` is true.

The verdict log gains decision ids that contain the repository, the head commit, the piece and the question. The tier judgment's ids are the pattern: an id without the run's identity would be scored once across every review.

`review-tools.yaml` gains a row the review runner ignores. Setup, when card C3 reads that file, will see the same fields it sees on the scanner rows.

## Risks & Dependencies

| Risk | What makes it smaller |
| --- | --- |
| Ctags names a method `member` in one language and something else in another, so a function is missed | The missed file uses the 20-line window and is marked degraded. The fake parser locks the contract. A corpus run is where a language gap shows up |
| One request can cross $1, because the token count arrives with the response | The sweep sends nothing further. The crossing request is listed in the spend, and its items count |
| The open side hides a defect by returning no items | `failed` is true and the degraded reason is set. The review continues, which is the side house rule 8 requires this card to name |
| C2's threshold row arrives with different keys | U3 raises on a calibration file that is not the expected shape, rather than treating it as an empty list |
| A hand-edited bundle copy drifts from `jev_sweep.py` | U5 commits only the bundler's output, and `bundle_fleet_module.py --check` fails a hand edit |

Depends on C1, which has landed, for the where-to-look fields and `review_records.validate`. Depends on C4a, which has landed, for `review_diff.read` and the tool list. C2 has not landed on this branch. C3, C7, C8, C10a, C11 and C15 are callers or inputs this card does not wait for.
