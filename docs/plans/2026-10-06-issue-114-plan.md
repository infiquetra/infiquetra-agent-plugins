# Give infiquetra-agent-plugins its own saga profile, including its functional-test declaration

## Summary

Add a tracked `.saga-profile.json` at the repository root so saga runs in this catalog stop asking the profile questions, and so the catalog declares a local, private functional-test environment whose test command is the plugin test suite.

The three live-profile tests in `plugins/saga/tests/` skip until that file exists. They require the whole profile, not the functional-test block alone. This plan pins every value those tests read, and the values the card left for planning to confirm.

## Problem Frame

Issue #97 added the functional-test block to the profile contract and named this repository's own profile as a file to change. The survey on 2026-10-04 found that any root profile turns on three tests, and those tests need the four profile parameters, `main_consumed_directly`, `nonproduction_destination` set to `none`, and a `qa` section. That is a decision about how saga treats this catalog, so it is this card rather than a change to the contract.

Without the file, admission keeps asking questions that are true of the repository every time. With a file that fails one of those tests, the suite that was skipping starts failing.

## Requirements

- R1. `.saga-profile.json` exists at the repository root and declares a functional-test environment with kind `local`, scope `private`, and the plugin test suite as the test command. It does not also carry a waiver.
- R2. The same file supplies `concurrency_allocation`, `nonproduction_destination` (`none`), `mechanical_tool_baseline`, and `preflight_checks`, plus `main_consumed_directly` and a `qa` block that validates against `plugins/saga/references/qa-profile.schema.json` with at least one required strategy, so the three live-profile tests run and pass.
- R3. `docs/engineering-journal/DECISIONS.md` records the declaration in the same change as the profile.

## Key Technical Decisions

- Local private functional-test environment, and no waiver: the card names `kind: local`, `scope: private`, and the plugin test suite as the likely declaration. The test command is `python3 -m pytest plugins/*/tests -q --import-mode=importlib`, which is the `plugin-tests` job in `.github/workflows/ci.yml` invoked with `python3`, the interpreter `AGENTS.md` and the card's verification use. `local` may omit `deploy_command`, and nothing is started, so there is no teardown. A waiver would say this catalog has nothing to run. Limiting the command to `plugins/saga/tests` would be narrower than the plugin suite the card names.
- `nonproduction_destination` is the string `none`: the card requires it, and `plugins/saga/tests/test_release_step.py` asserts that exact value before it will run. This catalog's workflow validates and tests. It does not deploy.
- `main_consumed_directly` is true: installed clients load this catalog from its own marketplace, and that marketplace checkout is this repository's `main`. False is the example in `plugins/saga/references/repository-profile.md`, and that example's `repo` field is `infiquetra/infiquetra-claude-plugins`, a different repository. False would tell the release worker it may issue the merge itself (`plugins/agent-launcher/roles/release-worker.md`).
- `concurrency_allocation` is the integer `10`: that is the only number the profile contract publishes. `plugins/saga/scripts/review_roster.py` ignores a value that is not a positive integer, so a string would look filled and then count as no allocation.
- The mechanical baseline is the continuous-integration commands that do not need the Claude Code CLI: `python3 scripts/check_repo.py`, `python3 -m unittest discover -s tests -v`, the plugin pytest command above, and `git diff --check`. The `claude-mods` job needs two pinned Claude Code installs. A baseline command that cannot start is not green, and the combined-branch pass then does not run the functional test. This repository's workflow does not run ruff, mypy, or bandit, so those catalogue checks stay uncovered rather than being added as commands this catalog has never gated on.
- The `qa` block requires `cli-smoke` and names one command, `python3 scripts/check_repo.py`. The live test only checks that the block matches the schema and that some strategy is required. `cli-smoke` is the catalogue row for a command-line catalog, its estimate is 120 seconds, and the ceiling must be at least that or the whole selection is refused. The ceiling is 180 seconds and a direct cost of 0. The smoke driver does not expand globs, so the command has none. `installed-surface` is rejected: its root lookup looks for a marketplace named `infiquetra-plugins`, and this catalog's marketplace is `infiquetra-agent-plugins`.
- `preflight_checks` are the two sentences the profile contract publishes. Nothing in this repository executes them, and the card does not name different ones.

## Implementation Units

### U1. Write the tracked profile and record the decision

One commit adds `.saga-profile.json` and the journal entry that says why those values are the ones saga will stop asking about.

**Goal:** Saga runs in this repository read a complete profile, the three live-profile tests run and pass, and the journal records the choice.

**Requirements:** R1, R2, R3

**Dependencies:** none

**Files:** `.saga-profile.json` (create), `docs/engineering-journal/DECISIONS.md` (insert one entry immediately after the `## 2026-10-06` heading). The tests that start running, and are not edited, are `plugins/saga/tests/test_admission.py`, `plugins/saga/tests/test_release_step.py`, and `plugins/saga/tests/test_qa_strategies.py`.

**Approach:** Create `.saga-profile.json` with this object and a trailing newline. Do not add `functional_test_waiver`, `branch_preview`, or `branch_preview_command`. `.saga/` is git-ignored; this file is not, and it must be tracked.

```json
{
  "schema": "repository_profile.v1",
  "repo": "infiquetra/infiquetra-agent-plugins",
  "concurrency_allocation": 10,
  "nonproduction_destination": "none",
  "main_consumed_directly": true,
  "functional_test_environment": {
    "kind": "local",
    "test_command": "python3 -m pytest plugins/*/tests -q --import-mode=importlib",
    "scope": "private"
  },
  "mechanical_tool_baseline": [
    "python3 scripts/check_repo.py",
    "python3 -m unittest discover -s tests -v",
    "python3 -m pytest plugins/*/tests -q --import-mode=importlib",
    "git diff --check"
  ],
  "preflight_checks": [
    "the plan cleared /doc-review with nothing above P3 open",
    "the work branch exists and is not the default branch"
  ],
  "qa": {
    "schema": "qa_profile.v1",
    "ceiling": {
      "max_duration_seconds": 180,
      "max_direct_cost": 0
    },
    "strategies": {
      "cli-smoke": {
        "required": true,
        "commands": [
          {
            "name": "repository-validation",
            "command": "python3 scripts/check_repo.py"
          }
        ]
      }
    }
  }
}
```

Insert this entry at the top of the existing `## 2026-10-06` section in `docs/engineering-journal/DECISIONS.md`, in the same commit as the profile.

```markdown
### This catalog's saga profile declares a local functional-test environment and no deploy destination

**Decision.** `.saga-profile.json` at the repository root declares `functional_test_environment` with kind `local`, scope `private`, and test command `python3 -m pytest plugins/*/tests -q --import-mode=importlib`. `nonproduction_destination` is `none`. `main_consumed_directly` is true. `concurrency_allocation` is 10. The mechanical baseline is `python3 scripts/check_repo.py`, `python3 -m unittest discover -s tests -v`, that same pytest command, and `git diff --check`. The `qa` block requires `cli-smoke` of `python3 scripts/check_repo.py`, with a ceiling of 180 seconds and no direct cost.

**Rationale.** Issue #114. The three live-profile tests skip until this file exists, and they require the whole profile. The plugin test suite is the test command the card names, and it is the command the `plugin-tests` job runs. This catalog does not deploy. Installed clients load it from this repository's marketplace on `main`, so a merge to `main` is consumed directly. The `qa` block is the smallest schema-valid block whose required strategy this catalog can run: `installed-surface` looks for a marketplace named `infiquetra-plugins`.

**Rejected alternatives.** A waiver. A deploy destination. `main_consumed_directly` false, copied from the profile contract's example for a different repository. The Claude Code matrix job on the mechanical baseline. `installed-surface` in the `qa` block.

**Revisit when.** This catalog gains a non-production deploy, or `installed-surface` resolves the `infiquetra-agent-plugins` marketplace.
```

**Patterns to follow:** the object shape in `plugins/saga/references/repository-profile.md`, the `qa` block shape in `plugins/saga/references/qa-profile.schema.json`, and the Decision / Rationale / Rejected alternatives / Revisit when entries already under `docs/engineering-journal/DECISIONS.md`.

**Test scenarios:**

- Happy path. The repository root contains the JSON above. Run `test_this_repositorys_own_profile_parses_and_fills_what_it_claims`, `TestDeploy::test_this_repositorys_profile_records_no_destination_and_deploys_nothing`, and `TestProfile::test_this_repositorys_own_qa_block_validates_against_the_profile_schema`. Each runs, the skip line `this catalog does not carry the upstream repository's .saga-profile.json` does not appear, and each passes.
- Edge. The file has `functional_test_environment` and has neither `functional_test_waiver` nor `branch_preview`. Resolving it returns mode `declared`, kind `local`, scope `private`. A file that carries both the environment and a waiver is refused, so this file carries one.
- Error. `nonproduction_destination` is the string `none`, not a JSON null. `concurrency_allocation` is a JSON number. The `qa` strategy id is `cli-smoke` and `required` is true. A `qa` block whose strategies are all optional fails the qa live test, and a missing ceiling fails it too.
- Integration. The release test reads `nonproduction_destination` from the file, calls deploy with a recording handoff stub, and gets status `no-destination`, `deployed` false, and no handoff call.

**Verification:** The three tests are collected and pass, with no skip. Resolving the profile reports a declared local environment. `python3 scripts/check_repo.py` and `git diff --check` are clean. The journal entry is in the same commit as the profile.

**Functional checks:**

```functional-checks

  command: |-
    python3 -c "import json,sys; from pathlib import Path; sys.path.insert(0,'plugins/saga/scripts'); import functional_environment; profile=json.loads(Path('.saga-profile.json').read_text()); resolved=functional_environment.resolve(profile); sys.exit(0 if resolved and resolved.get('mode') in ('declared','waived') else 1)"
  proves: [AC-1]

- name: live-profile-tests-run
  command: |-
    python3 -c "import pytest,sys; skipped=[]; P=type('P',(),{'pytest_runtest_logreport':lambda self, report: skipped.append(report.nodeid) if report.skipped else None}); code=pytest.main(['-q','--import-mode=importlib','plugins/saga/tests/test_admission.py::test_this_repositorys_own_profile_parses_and_fills_what_it_claims','plugins/saga/tests/test_release_step.py::TestDeploy::test_this_repositorys_profile_records_no_destination_and_deploys_nothing','plugins/saga/tests/test_qa_strategies.py::TestProfile::test_this_repositorys_own_qa_block_validates_against_the_profile_schema'], plugins=[P()]); sys.exit(code or (1 if skipped else 0))"

```

A bare pytest of those three tests exits 0 when all three skip, which is what they do while the file is absent. The second check exits non-zero when any of them is skipped.

## Scope Boundaries

The change is the profile and the journal entry. The profile contract, the three tests' skip guards, and the saga run record stay as they are.

**Out of scope:**

- No change to the profile contract. Issue #97 owns that.
- No edit to the three live-profile tests. Their skip remains the behavior of a catalog that has no profile. This catalog stops taking that branch because the file exists.
- No Claude Code matrix job, ruff, mypy, or bandit on the mechanical baseline.

**Deferred to follow-up work:**

- Declare `installed-surface` once its driver resolves the `infiquetra-agent-plugins` marketplace. Today it looks for `infiquetra-plugins`.
- Add the `claude-mods` continuous-integration job to the mechanical baseline once a local command exists that does not need two pinned Claude Code installs.

## Risks

A required `cli-smoke` whose command fails blocks a later `/qa` run instead of re-entering the build loop. The command is `python3 scripts/check_repo.py`, which the hermetic validation job already runs, so a failure there is the catalog's own gate and not a new one.

`main_consumed_directly` true makes the release worker wait for the operator's prior approval before issuing the merge. That is the point of the value. The journal entry is what a later reader uses to change it.
