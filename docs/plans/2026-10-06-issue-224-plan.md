# The calibration file accepts the corpus's languages and records the measured reviewer's configuration (issue #224)

## Summary

Saga's calibration schema accepts the corpus's language ids and records the measured reviewer as an object instead of a single fingerprint. The workflow id becomes `github-workflow` everywhere saga uses it, `cdk` joins every language list, `reviewer_configuration` validates field by field with `null` still accepted, and the review-time comparison reads `configuration_fingerprint`. A landed `fingerprint(root)` builder and a case-id fallback in `load_corpus` complete the card.

---

## Problem Frame

This is card #224 of the saga review redesign program (parent issue #147). It unblocks the corpus harness (saga-review-corpus#3), which writes the calibration file and is refused twice by saga's schema today: the harness writes verdicts under the corpus's language ids, and it writes the measured reviewer as an object. The harness must not map one language onto another, so saga owns the answer.

Measured current state, checked before planning:

| The corpus on saga-review-corpus main | Saga today |
| --- | --- |
| `corpus/case.py` `LANGUAGES` holds ten ids: `cdk`, `cloudformation`, `dart`, `github-workflow`, `markdown`, `python`, `rust`, `shell`, `swift`, `typescript` | `review_formula.LANGUAGES` (`plugins/saga/scripts/review_formula.py:46`) holds `github-workflows` (plural), has `cloudformation`, and has no `cdk` |
| Cases carry their id as `id` (`REQUIRED` in `corpus/case.py`) | `review_dataset.load_corpus` (`plugins/saga/scripts/review_dataset.py:65`) requires `case_id` |
| The harness writes `reviewer_configuration` as `{vendor, model, effort, prompt_sha256, configuration_fingerprint, second, cleared_components}` (`corpus/harness/outputs.py`, `ReviewerConfiguration`) | `document_problems` (`plugins/saga/scripts/review_calibration.py:271`) requires a 64-hex string or null and refuses the object |

Two notes on the card's wording. First, the card says saga has no `cloudformation`; measured, `review_formula.py:55` already lists it, so this plan adds only `cdk` and settles the workflow spelling. Second, the card's file list omits the synchronized copies of the language list: the record schemas, the answer schema, the question banks, and fleet-core's sweep source hold the same tuple under drift tests, so the rename touches them too (U1 names every file).

The remaining gaps are small. `review_command.py` compares one fingerprint (`:958`, `_reviewer_configuration` at `:1364`), so it must read `configuration_fingerprint` from the object. The component fingerprint builder exists only as the calibration test helper (`plugins/saga/tests/test_review_calibration.py:103`), and the committed calibration file is still `no-run` with `reviewer_configuration: null`, so no stored file migrates.

## Requirements

Requirements are grouped by concern; R-IDs run continuously.

**Languages**

- R1. `review_formula.LANGUAGES` holds `cdk` and `github-workflow`, and no `github-workflows`. `question_banks.LANGUAGES`, fleet-core's `jev_sweep` `LANGUAGES` with its regenerated `_bundled` copy, and the language enums in `review-records.schema.json` and `targeted-reviewer-answer.schema.json` match it exactly, so the three drift tests hold unchanged.
- R2. Every site that detects, labels, or lists the workflow id uses `github-workflow`: `review_tools.language_for`, the setup survey, the two `review-tools.yaml` entries, and the workflow adapter's findings. The prose language lists in the reviewer prompt and the records reference are updated.
- R3. A recorded calibration file may hold verdicts for `cdk`, `cloudformation`, and `github-workflow`, and `may_block` answers for every corpus language id (the ten ids in `corpus/case.py` on saga-review-corpus main).

**Reviewer configuration**

- R4. `reviewer_configuration` accepts null or the object `{vendor, model, effort, prompt_sha256, configuration_fingerprint, second, cleared_components}`, each field validated. A malformed file is refused naming the field. The legacy 64-hex string form is refused.
- R5. Saga's review-time comparison reads `configuration_fingerprint` from the object. A null configuration notes every run, as today.

**Fingerprint builder and dataset**

- R6. `review_calibration.fingerprint(root)` returns the sha256 of every `COMPONENTS` path through `locate`. The calibration test helper uses it. The repository check's fingerprint rule is unchanged.
- R7. `review_dataset.load_corpus` reads a case's `id` when `case_id` is absent. `case_id` wins when both are present. Neither is still refused.

**Docs**

- R8. `review-calibration.md` documents the object and keeps every phrase its drift test pins. The saga and fleet-core changelogs gain entries under `[Unreleased]`. No version is bumped.

## Key Technical Decisions

- KTD1. Rename `github-workflows` to `github-workflow` everywhere; no alias table: the corpus already uses the singular, nothing stored migrates (the committed file is `no-run` with no verdicts, and no corpus run is recorded), and the drift tests already force synchronized edits across the formula, both schemas, the banks, and the sweep source. The rename's remaining sites (the tool list, the detector, the setup survey, the adapter, two prose docs) are mechanical one-word changes. Rejected: keeping the plural behind an alias table, which would leave two spellings in stored records permanently and require every future reader to normalize.
- KTD2. `cdk` joins the language enumerations but no finding is relabeled: the infrastructure adapter keeps reporting `cloudformation`. The card asks only that verdicts and `may_block` accept the ids. Relabeling CDK findings is a later item.
- KTD3. Object field rules: every field is required (`second` may be null, `cleared_components` may be empty); `vendor`, `model`, and `effort` are identifiers; `prompt_sha256` and `configuration_fingerprint` are 64-hex sha256; `second` is null or exactly `{vendor, model, effort}` as identifiers with no extra keys; `cleared_components` is a list of unique non-empty strings. Its entries are harness-config component names (switchable reviewer components in the harness's `components.py`), not saga `COMPONENTS` paths, so membership is not checked. Unknown keys on the object are refused, matching the top-level strictness.
- KTD4. The legacy 64-hex string form is refused, not migrated: nothing recorded it yet (the committed file carries null), so there is nothing to migrate and no dual reader to maintain. `review_command._reviewer_configuration` returns the object's `configuration_fingerprint`, or null when the field is null or the file is unreadable.
- KTD5. `fingerprint(root)` hashes through `locate`, in `COMPONENTS` order, returning `{relative: sha256}`, so packaged installs resolve correctly. The test helper delegates to it, leaving one loop. A missing component raises, naming the path: the builder fails closed.
- KTD6. `load_corpus` prefers `case_id` (existing callers and staged harness folders are unchanged), falls back to a non-blank `id`, and normalizes the resolved id back onto `case_id` on the returned dicts, so `dataset_item` and `item_id` are unchanged. Both absent or blank is refused with the existing message.

### U2. `reviewer_configuration` as the measured reviewer's object

A calibration file records which reviewer the bake-off measured, field by field, and review time compares against it.

**Goal:** `document_problems` accepts null or the documented object, refuses malformed objects naming the field, and the review-time comparison reads `configuration_fingerprint`.

**Requirements:** R4, R5; KTD3, KTD4.

**Dependencies:** U1 (shared calibration test file).

**Files:**
- `plugins/saga/scripts/review_calibration.py`
- `plugins/saga/scripts/review_command.py`
- `plugins/saga/references/review-calibration.md`
- `plugins/saga/tests/test_review_calibration.py`
- `plugins/saga/tests/test_review_command.py`

**Approach:**
- Add a `_reviewer_problems` helper beside `_lens_problems`: null passes; any non-object (including the legacy string) fails as `reviewer_configuration`; an object fails per field, each problem naming `reviewer_configuration.<field>`. Every field is required: `second` may be null and `cleared_components` may be empty, but a missing key fails, including a missing key inside `second`. Unknown object keys are refused. `vendor`, `model`, and `effort` match `IDENTIFIER`; both sha fields match `SHA256`; `second` is null or an object with exactly identifier `vendor`, `model`, and `effort`; `cleared_components` is a list of unique non-empty strings. `document_problems` calls it where the string check sits today.
- `review_command._reviewer_configuration` returns `_hex_or_none` of the object's `configuration_fingerprint`, else null. The noted-reviewers logic around it is unchanged: a mismatch or a null configuration still notes `reviewer-configuration`.
- `review-calibration.md` documents the object in the `reviewer_configuration` row: each field, `second` as null or `{vendor, model, effort}`, and `cleared_components` as harness-config component names cleared by a no-change comparison. Keep every phrase the reference test pins: the component list, the `adds its paths in the same change` rule, the instruction-files sentence, and the install/base/head wording.

**Patterns to follow:** the `_lens_problems` validator shape and its `_ident`/`_unknown` problem strings (`plugins/saga/scripts/review_calibration.py:133`); the noted-reviewer test (`plugins/saga/tests/test_review_command.py:1359`); the reference drift test (`plugins/saga/tests/test_review_calibration.py:699`).

**Test scenarios:** each name contains `reviewer_configuration`.
- `test_reviewer_configuration_object_validates`: the harness shape validates, with `second` as an object and a non-empty `cleared_components` list; and again with `second` null and the list empty.
- `test_reviewer_configuration_malformed_field_is_refused_by_name` (parametrized): a bad `vendor`, a short `prompt_sha256`, a non-hex `configuration_fingerprint`, `second` as a string, `second` with an extra key, `cleared_components` holding a non-string, `cleared_components` with a duplicate, and an unknown key on the object are each refused with the field named.
- `test_reviewer_configuration_missing_key_is_refused_by_name` (parametrized): removing each object key in turn, and removing each key inside `second` in turn, is refused naming that field.
- `test_reviewer_configuration_null_validates_and_string_is_refused`: null passes; the legacy 64-hex string fails.
- `test_reviewer_configuration_recorded_fixtures_still_validate`: the existing `_recorded` helper output and the committed file have no problems (the brief's keep-validating direction).
- `test_reviewer_configuration_comparison_reads_the_fingerprint`: a recorded calibration carrying the object, finished with a matching run, notes no `reviewer-configuration`; a differing run notes it with both fingerprints; a null configuration notes every run. This extends the noted-reviewer test, renamed to carry `reviewer_configuration`.

**Verification:** the object validates, a malformed object is refused with the field named, null still validates, and the review record notes a configuration mismatch.

**Functional checks:**


## Scope Boundaries

**In scope:** the language ids saga accepts, the reviewer object, the review-time comparison, the fingerprint builder, the `id` fallback, the calibration reference, and both changelogs.

**Non-goals (from the card):**
- Renaming the corpus's language ids: the corpus is never changed.
- The corpus harness itself, and the bake-off.
- Changing any threshold, question, or outcome mapping.

**Deferred to follow-up work (later items, not units):**
- Relabeling CDK findings to `cdk`: the infrastructure adapter keeps reporting `cloudformation` (KTD2). A verdict for `cdk` gates nothing until a finding carries the id.
- A run-scoped queue status in `review_trace.py`: the harness's per-run homes suffice, and the card does not ask for it.
- Migrating the old plural id out of local run records or Langfuse traces, if any exist: nothing committed carries verdicts yet.

## Risks & Dependencies

- **A malformed calibration file validates.** The file decides which lenses may block, so this is the card's medium risk. Mitigation: per-field refusal tests in both directions (U2 pins that malformed files fail and valid files pass), unknown-key strictness at both levels, and the committed null-form file covered by the suite.
- **The rename misses a site.** Mitigation: the drift tests fail loudly on any tuple mismatch, the bundle check rejects a stale `_bundled` copy, and U1 ends with a repository-wide search.
- **No dependency on issue #223** (reviewer recipes and the spending ceiling): recording the measured reviewer's shape does not depend on launching it. The harness picks this up at its next saga pin, which is the harness's change, not this card's.
