# The calibration file decides which lenses may block (issue #149)

## Summary

Add a calibration file in saga that stores the pass marks from the review-redesign design, records that no corpus run exists yet, and answers whether a lens may block in a language. One fingerprint of the review's components lives in saga. `scripts/check_repo.py` calls it, and until a run is recorded the check accepts any fingerprint.

---

## Problem Frame

This is card C2 of the saga review redesign (parent issue #147). The review command (C10a) will ask this file whether a lens may block. The corpus harness (K3) will write the verdicts. The formula (C1, issue #148) already takes the answer as data and does not read the file itself.

Today the decision sits outside this repository. The lifecycle repository's executor-verification ledger, `config/executor-verifications.json` in infiquetra-sdlc, has an empty `entries` list on purpose, so no lens sets a threshold. `plugins/saga/skills/code-review/SKILL.md` (the "refused report is expected today" paragraph) says every code review ends `review_incomplete`. `plugins/saga/scripts/review_consensus.py` returns that outcome when a lens has no usable result. `scripts/check_repo.py` (`check_repo`) runs fourteen checks, and none of them is about review calibration.

C1, C4a (issue #151) and C8 (issue #158) have already landed on this branch. The formula and the record schema exist. C4a published `FINGERPRINT_COMPONENTS` and a test that fails if `review_calibration.py` exists and omits those paths. C8 published the reviewer prompt, the answer schema and the launch settings, and left them off the fingerprint because this file did not exist. The pass marks are already fixed in the design's "How we'll know it works" and "Per-language guard" and "Repeat runs" sections. This card stores them. It does not change them, and it does not run the corpus.

---

## Requirements

Requirements are grouped by concern. R-IDs run continuously.

**The file and the marks**

- R1. `plugins/saga/references/review-calibration.json` is the committed file. It spells "no run yet" as `corpus_run` equal to `no-run`, lists every lens from `review_formula.LENSES` with drift `report-only` and no language verdicts, and holds an empty `thresholds` list (AC-2).
- R2. The pass marks, the per-language guard, the repeat-run rule and the deterministic rule are stored under `marks` as integers and one identifier, equal to the design's `plan.md`. The harness reads that object and this card never rewrites it (AC-2).
- R3. `plugins/saga/references/review-calibration.md` documents every field, every kind of component the fingerprint covers, that the reviewer's launch settings and the cached Semgrep rule packs are on the list, and that a card which adds a review component adds its paths in the same change (AC-1).

**The fingerprint**

- R4. One function in `plugins/saga/scripts/review_calibration.py` hashes the component list. `scripts/check_repo.py` calls that function through a local import. `check_repo.py` stays on the standard library and does not import the saga module at module scope (AC-6).
- R5. While `corpus_run` is `no-run`, the fingerprint check passes no matter what the component bytes are. Once `corpus_run` is `recorded`, a matching fingerprint passes, a one-byte change to a listed component fails and names that path, and a missing listed path fails and names that path (AC-3).
- R6. A key outside the format fails, and free text outside an identifier field fails, whether or not a run is recorded (AC-5).

**The answer**

- R7. `python3 plugins/saga/scripts/review_calibration.py may-block --lens security --language python` prints the answer and its reason on one line and exits 0. On the committed file the line is `report-only no-run` (AC-4).
- R8. The answer is `yes` only when a run is recorded, the fingerprint matches, the lens's drift line is `as-recorded`, the language's verdict is `cleared`, and no tool that serves the lens is pinned off its default. A `report-only` verdict stays report-only when the stored numbers would clear the marks. The reader never compares numbers with the marks (AC-5).
- R9. The answer is report-only, with the reason named, for no run, a stale fingerprint, a drift line of `report-only` (every language of that lens), a language with no verdict, and a profile pin of another version or rule set on a tool that serves the lens (AC-5).
- R10. Thresholds read back as stored. The committed file's list is empty (AC-5).
- R11. The new script's `--help` exits 0 with credential variables removed, and `plugins/saga/tests/test_entrypoints.py` picks the script up with no edit to that test (AC-5).
- R12. No test and no command in this change opens a network connection (AC-5).

## Key Technical Decisions

Each entry is the decision, then why, naming what was rejected.

- **KTD1. The spelling of "no run yet" is the identifier `no-run` on `corpus_run`.** A recorded run is the identifier `recorded`. The check treats only `recorded` as a run. Anything else, including a missing key, is a format error, so a typo cannot fall through into "any fingerprint passes". Rejected: JSON `null` (easy to miss in review), and a missing key meaning no run (a deleted key would silently disable the gate).
- **KTD2. The drift switch is one field per lens, `drift`, valued `report-only` or `as-recorded`.** Changing that one line to `report-only` makes every language of that lens report only, even when a language verdict is `cleared` and the stored numbers would clear the marks. `as-recorded` means "read the language verdict". Rejected: a per-language drift flag (the monthly run would have to edit every language), and deleting the language objects (that is not a one-line change, and it throws away the numbers K3 recorded).
- **KTD3. The reader answers from verdicts and never applies the marks.** `marks` is data the harness reads. `may-block` does not import the mark numbers into the decision. A cleared verdict beside numbers that miss the marks still answers `yes`. A report-only verdict beside numbers that clear the marks still answers `report-only`. Rejected: recomputing clearance in saga (that is K3's job, and a second implementation of the marks would let the two disagree).
- **KTD4. The component list this card commits is ten repo-relative paths, written as string literals in `review_calibration.py`.** C1's two paths are this card's own addition. C4a's five paths are included because C4a landed first: its card says the card that lands second adds them, and `plugins/saga/tests/test_review_tools.py` (`test_fingerprint_names_these_paths`) reads this file as text and requires each path to appear. C8's three paths are included because C8 landed first and its plan's unit for the join stopped rather than create this file; the planning note says the launch settings join by the path of the file C8 keeps them in. Cards that have not landed append their own paths later. The code-review repair appends C6's three `SWEEP_COMPONENTS` paths as further literals, for the same reason: that card's test fails if this file exists and omits them. Rejected: only C1's two paths (the existing C4a test fails the moment this file exists, and the reviewer prompt already in the tree would change with no corpus run), and importing C4a's tuple so the path strings are not in this file (the existing test searches the source text).
- **KTD5. The Semgrep pack is covered by the sha256 already stored beside its pin in `review-tools.yaml`, not by hashing a cache directory and not by committing the pack.** That yaml is on the list, so a pin change changes the fingerprint. The pack bytes stay out of this public repository. The decision dated 2026-10-06 in `docs/engineering-journal/DECISIONS.md` records the license reason. Rejected: hashing the operator's Semgrep cache (it is outside the repository, and `check_repo.py` would then depend on a machine-local directory).
- **KTD6. The reviewer configuration is a field on the file and is not a fingerprinted component.** It is `null` until K3 writes a sha256 of the instruction files and enabled plugins the run measured. `may-block` does not read it. A change to `CLAUDE.md`, `AGENTS.md`, or a plugin manifest fails no fingerprint check. Saying that a live review's configuration differs is C10a's job. Rejected: putting instruction files on the component list (every edit of those files would demand a corpus run).
- **KTD7. The fingerprint is a map of component path to sha256 of the file bytes.** One function computes it. `check_repo.py` and `may-block` both call it. A mismatch names the path whose bytes differ. A missing file names that path. While `corpus_run` is `no-run`, that comparison is skipped. Rejected: one combined hash (a failure could not name the component).
- **KTD8. `review_calibration.py` imports only the standard library at module scope, and imports PyYAML only inside the pin comparison, by importing `review_tools` there.** `check_repo.py` calls the format check and the fingerprint check, which never reach that import, so `python3 scripts/check_repo.py` does not need PyYAML. The pin comparison uses `review_tools.load_tool_list` on the root's `review-tools.yaml` so there is one reader of the default tool list. This card does not edit `review_tools.py`. Rejected: a top-level `import yaml` (the repository check would fail where PyYAML is not installed), and a second YAML parser in this module.
- **KTD9. A tool serves a lens when a row of the default tool list has that `lens` and a non-empty `tool`.** The tool list is `load_tool_list` of `<root>/plugins/saga/references/review-tools.yaml`, the same root as the calibration file and the profile. A pin differs from the default when `review_tools.pins.<tool>.version` is a string other than that row's `default_version`, or when `rules` is present and its pack, path and sha256 list is not equal to that row's `rules`. A version-only pin keeps the yaml rules, which is the rule `repository-profile.md` already states. The first differing tool in tool-list order is the one the reason names. One binary can serve two lenses: semgrep has a security row and a correctness row, so a version pin off the default makes both report only. An absent profile, an absent `review_tools` block, and an absent `pins` key are no difference and do not load the tool list. A malformed profile makes `may-block` exit 2 and print no `yes`. Malformed means anything `review_tools._load_profile` would refuse: the file is not JSON; the top level is not an object; `functional_test_environment` is present and not an object, or its `test_command` is present and not a string; `review_tools` is present and not an object; `languages` is present and not an object, names a language outside `LANGUAGES`, holds a non-object value, or holds a `test_command` or `coverage_report` that is not a string; `pins` is present and not an object; a pin names a tool with no non-empty `tool` on a row of that root's tool list; a pin value is not an object; `version` is present and not a string; `rules` is present and not a list; a rules entry is not an object or has neither `pack` nor `path`; a `sha256` is present and is not 64 hex characters; a pack entry has no 64-hex `sha256`. The unknown-tool check uses that root's tool list, not the checkout that contains the script. Rejected: treating any pin, including one that repeats the default, as report-only (a profile that restates the default would turn a cleared lens off), and calling `load_tool_list()` with no path (an overridden root would be compared with the wrong defaults).
- **KTD10. The reason order is fixed, and the first match wins.** No run, then a stale or missing fingerprint, then drift `report-only`, then no verdict for the language, then a pin off the default, then a report-only verdict, then `yes` with reason `cleared`. An unknown lens or an unknown language exits 2 and does not answer. A malformed file exits 2 and does not answer. The default is never `yes`. Rejected: answering report-only for a malformed file (a broken file would look like a real verdict).
- **KTD11. Identifier fields are a closed charset with no spaces.** Enumerated values are the tokens this plan names. Counts and the cost are JSON numbers. A string with a space, or a string that fails its field's pattern, is free text and fails the check. This is what makes the file safe to commit in a public repository. Rejected: a prose `note` field (the card forbids free text outside identifier fields).
- **KTD12. The check is required only when `plugins/saga` is in the tree being checked.** A fixture tree with no saga package passes. A tree that has `plugins/saga` and no calibration file fails, naming `plugins/saga/references/review-calibration.json`. The import path is `plugins/saga/scripts` beside `check_repo.py`, inserted inside the check function, matching `check_marketplace_manifest`. Rejected: requiring the file in every tree `check_repo` is pointed at (the existing temp-tree tests would start failing for a file they have no reason to carry).

## High-Level Technical Design

The committed file is JSON. `schema` is `review_calibration.v1`. Top-level keys, and no others:

| Key | No-run value | Recorded value |
|---|---|---|
| `corpus_run` | `no-run` | `recorded` |
| `fingerprint` | `{}` | one sha256 per component path |
| `corpus_version` | `null` | an identifier |
| `jev_model_version` | `null` | an identifier |
| `cost_usd` | `null` | a number, zero or greater |
| `langfuse_run_id` | `null` | an identifier |
| `reviewer_configuration` | `null` | 64 hex characters, or stays `null` |
| `marks` | the fixed object below | the same object, unchanged |
| `lenses` | every lens, drift `report-only`, `languages` `{}` | the same keys, with overall numbers and language verdicts |
| `thresholds` | `[]` | a list of question rows |

`marks` uses numerator and denominator integers, not floats:

| Lens id | Must block | May block of clean changes |
|---|---|---|
| `security` | 9 / 10 | 1 / 10 |
| `testing` | 9 / 10 | 1 / 10 |
| `correctness` | 8 / 10 | 1 / 10 |
| `architecture-maintainability` | 6 / 10 | 1 / 20 |

The language guard is `must_catch` 7 / 10 and `may_block_clean` 2 / 10. The repeat-run rule is `may_flip` 1 / 10. `deterministic` is the identifier `identical` (the same grade every time the deterministic part sees the same input). The design's lens name "Architecture and maintainability" is the formula's id `architecture-maintainability`.

A recorded lens looks like this. Counts are non-negative integers. `verdict` is `cleared` or `report-only`.

```json
{
  "drift": "as-recorded",
  "overall": {
    "held_out_blocked": 9,
    "held_out_defects": 10,
    "held_out_false_blocks": 1,
    "held_out_clean": 10,
    "repeat_flips": 0,
    "repeat_cases": 10
  },
  "languages": {
    "python": {
      "verdict": "cleared",
      "held_out_blocked": 9,
      "held_out_defects": 10,
      "held_out_false_blocks": 0,
      "held_out_clean": 10,
      "repeat_flips": 0,
      "repeat_cases": 10
    }
  }
}
```

On a no-run lens, `overall` is absent and `languages` is `{}`. On a recorded lens, `overall` is required and `languages` may still omit a language; `may-block` then answers `no-verdict` for that language.

A threshold row is `question` (an identifier), `threshold` (a JSON number) and `piece_size` (a positive integer). No other keys. An empty list means the sweep takes its 30 most likely items. C6 implements that behaviour. This card only stores the list.

`may-block` prints one line and exits 0:

| Situation | Line |
|---|---|
| `corpus_run` is `no-run` | `report-only no-run` |
| fingerprint differs or a component file is missing | `report-only stale-fingerprint <path>` |
| `drift` is `report-only` | `report-only drift` |
| the language has no verdict | `report-only no-verdict` |
| a serving tool is pinned off its default | `report-only pinned-tool <tool>` |
| the verdict is `report-only` | `report-only verdict` |
| the verdict is `cleared` and the rows above do not apply | `yes cleared` |

Exit 2 writes one line to stderr and prints no answer. The component list, in order:

1. `plugins/saga/scripts/review_formula.py`
2. `plugins/saga/references/review-records.schema.json`
3. `plugins/saga/scripts/review_tools.py`
4. `plugins/saga/scripts/review_diff.py`
5. `plugins/saga/scripts/coverage_lines.py`
6. `plugins/saga/scripts/review_adapters_all_languages.py`
7. `plugins/saga/references/review-tools.yaml`
8. `plugins/saga/references/targeted-reviewer-prompt.md`
9. `plugins/saga/references/targeted-reviewer-answer.schema.json`
10. `plugins/saga/references/targeted-reviewer-launch.json`
11. `plugins/fleet-core/scripts/fleet_commons/jev_sweep.py`
12. `plugins/saga/scripts/sweep_pieces.py`
13. `plugins/saga/references/model-prices.yaml`

Paths 3 to 7 are `review_tools.FINGERPRINT_COMPONENTS`, copied as literals. Paths 8 to 10 are the prompt, the answer schema, and the launch settings (vendor and model). Paths 11 to 13 are `sweep_pieces.SWEEP_COMPONENTS`, copied as literals by the code-review repair, because that card merged while this file existed and its test reads the sequences this module defines. `review_records.py` is not on the list. The schema file is the contract C1 fingerprints; the validator is held to that schema by C1's own drift test.

Identifier pattern for versions, run ids, question ids and corpus versions: `^[A-Za-z0-9][A-Za-z0-9._:/-]*$`. A sha256 is `^[0-9a-f]{64}$`. A component path in `fingerprint` must be one of the paths above.

## Implementation Units

### U1. The file, the marks and the format check

Commit the no-run file and the module that accepts exactly the format above.

**Goal:** The repository has a calibration file that says no corpus run exists, and a checker that refuses a key or a sentence that does not belong there.

**Requirements:** R1, R2, R6, R10, R12.

**Dependencies:** None. C1's `review_formula.LENSES` and `review_formula.LANGUAGES` are already on the branch.

**Files:**

- `plugins/saga/references/review-calibration.json` (new)
- `plugins/saga/scripts/review_calibration.py` (new)
- `plugins/saga/tests/test_review_calibration.py` (new)

**Approach:** The module reads and validates JSON with the standard library. It exposes the marks as a constant the committed file's `marks` object equals, and a `thresholds` function that returns the list. It does not write the file. Lens ids come from `review_formula.LENSES`. Do not import `review_tools` or PyYAML in this unit. Validation failures name the dotted key (`unknown key: …`, `not an identifier: …`).

**Patterns to follow:** `plugins/saga/scripts/review_formula.py` for a standard-library script, and `plugins/saga/references/targeted-reviewer-launch.json` for two-space JSON with a trailing newline.

**Test scenarios:**

Name the tests so the unit's `-k` filter selects them. `test_committed_file_is_no_run`, `test_thresholds_read_back`, `test_stored_marks_equal_plan`. An autouse fixture makes `socket.socket.connect` and `socket.create_connection` raise, and the module stays green. U3 lives in this file, so the same fixture covers it.

- Happy path, `test_committed_file_is_no_run`: the committed file has `schema` `review_calibration.v1`, `corpus_run` `no-run`, `fingerprint` `{}`, nulls on the five recorded identifiers and the cost, `thresholds` `[]`, and one object per lens in `LENSES` with `drift` `report-only` and `languages` `{}`.
- Happy path, `test_thresholds_read_back`: `thresholds()` on the committed file returns `[]`. A temporary file with one threshold row (`question` `security.secret-in-diff`, `threshold` `0.8`, `piece_size` `40`) reads back those three values unchanged.
- `test_stored_marks_equal_plan` parses the table under "How we'll know it works" in `docs/brainstorms/2026-10-05-saga-review-redesign/plan.md` whose header contains `Must block, of known blocking defects`. Column 1 is the lens name, column 2 the must-block cell, column 3 the may-block cell, each cell holding `N in D`. `Architecture and maintainability` maps to `architecture-maintainability`. The other three names are lowercased. The sentence containing both `fewer than 7 of 10` and `more than 2 of 10` supplies the guard (must catch 7/10, may block of clean changes 2/10). The "Repeat runs" sentence containing `more than 1 in 10` supplies `may_flip` 1/10. The "How we'll know it works" sentence containing `the same grade every time` is what `deterministic` equal to `identical` records. The constant and the committed file's `marks` both equal those fractions.
- Error path: a temporary file with an extra top-level key `comment` fails validation and the error contains `comment`. A `langfuse_run_id` of `a sentence with spaces` fails and the error names `langfuse_run_id`. A `verdict` of `looks good` fails. A `corpus_run` of `maybe` fails.
- Edge case: a recorded lens may omit a language. An unknown lens key inside `lenses` fails. Counts are integers; the string `"9"` in a count fails.

**Verification:** The committed file loads, the marks test passes, and a file with an extra key is refused by name.

**Functional checks:**

```functional-checks
- name: stored-marks-match-plan
  command: python3 -m pytest plugins/saga/tests/test_review_calibration.py -q --import-mode=importlib -k "marks or no_run or thresholds"
  proves: [AC-2, AC-5]
  runs: local
```

### U2. One fingerprint, called from the repository check

Hash the ten paths in one function, and make `check_repo.py` call it.

**Goal:** A change to a listed review component fails the repository check once a corpus run is recorded, and names the file that changed. Before any run, the same check passes.

**Requirements:** R4, R5, R6, R12.

**Dependencies:** U1.

**Files:**

- `plugins/saga/scripts/review_calibration.py`
- `scripts/check_repo.py`
- `tests/test_check_repo.py`

**Approach:** Add `COMPONENTS`, the ten literals from the High-Level Technical Design, in that order. The digest is sha256 of the file bytes, lowercase hex. `check(root)` validates the JSON at `root / plugins/saga/references/review-calibration.json` and, only when `corpus_run` is `recorded`, compares the digest of each component with the recorded map. A changed file produces `changed component: <path>`. A missing file produces `missing component: <path>`. While `corpus_run` is `no-run`, skip that comparison. If `plugins/saga` is absent, return no errors. If it is present and the JSON is absent, return `missing calibration file: plugins/saga/references/review-calibration.json`.

`check_review_calibration` in `scripts/check_repo.py` inserts `plugins/saga/scripts` (the directory beside this script's repository, not `sys.path` from the tree under test) inside the function and imports `review_calibration` there, with the same local-import comment style as `check_marketplace_manifest`. `check_repo()` calls it. Do not import PyYAML in `check_repo.py`.

The recorded fingerprint's keys must be exactly `COMPONENTS`. A key that is not a component is `unknown key`. A missing key is `changed component` for that path.

**Patterns to follow:** `scripts/check_repo.py` function `check_marketplace_manifest` for the local import, and `tests/test_check_repo.py` class `GateWiringTests` for a test that the aggregate `check_repo` actually runs the new check.

**Test scenarios:**

Put these tests in `unittest` class `ReviewCalibrationTests` inside `tests/test_check_repo.py`. The functional check loads that class by name.

- Happy path, no run: a temp tree with `plugins/saga`, the committed no-run document, and the ten component files. After one byte is appended to `review_formula.py`, `check_review_calibration` returns `[]`.
- Happy path, recorded: the same tree with `corpus_run` `recorded` and a fingerprint computed from those files. `check_review_calibration` returns `[]`.
- Error path: the same recorded tree, one byte appended to one component. Both `check_review_calibration` and `check_repo` report `changed component:` and that path, and do not name the other nine.
- Error path: the recorded tree with that component file deleted. The error is `missing component:` and the path.
- Error path: an unknown key, and a free-text `langfuse_run_id`, each fail on their own and name the key. These two do not require a recorded run.
- Edge case: a temp tree with no `plugins/saga` returns `[]` from `check_review_calibration`.
- Integration: a temp tree whose only calibration fault is an unknown key makes `check_repo` report that key. A subprocess imports `check_repo`, calls `check_review_calibration` on the live repository, and asserts `yaml` is not in `sys.modules`. A second subprocess does the same on a recorded temp tree, so the fingerprint compare itself does not load PyYAML.
- Integration: monkeypatch `review_calibration.check` so it returns a one-element list containing the sentinel `sentinel-calibration`. `check_repo` on a temp tree reports that sentinel. A second hashing copy inside `check_repo.py` is not what the patch replaced, and a missing call would not surface the sentinel.
- The gate test reads `check_repo.py` and asserts `import review_calibration` appears only inside the function (indented), and asserts `import yaml` does not appear in that file.
- `setUp` makes `socket.socket.connect` and `socket.create_connection` raise for every test in the class.
- `test_fingerprint_names_these_paths` in `plugins/saga/tests/test_review_tools.py` already requires the five C4a paths to appear in this file. Do not edit that test. Add an assertion in the saga calibration tests that `COMPONENTS` equals C1's two paths, then `review_tools.FINGERPRINT_COMPONENTS`, then C8's three paths, then `sweep_pieces.SWEEP_COMPONENTS`.

**Verification:** `python3 scripts/check_repo.py` passes on the real tree. The temp-tree tests pass, and the live test `test_live_repository_passes_every_check` still passes.

**Functional checks:**

```functional-checks
- name: fingerprint-gate-names-the-component
  command: python3 -m unittest tests.test_check_repo.ReviewCalibrationTests -v
  proves: [AC-3, AC-5, AC-6]
  runs: local
- name: live-repository-check-passes
  command: python3 scripts/check_repo.py
  proves: [AC-3]
  runs: local
```

### U3. The may-block answer

Answer from the verdicts, the drift line, the fingerprint and the profile pins.

**Goal:** A caller can ask whether the security lens may block for Python, and get the answer and the reason, with no network call.

**Requirements:** R7, R8, R9, R11, R12.

**Dependencies:** U1, U2.

**Files:**

- `plugins/saga/scripts/review_calibration.py`
- `plugins/saga/tests/test_review_calibration.py`

**Approach:** Subcommand `may-block` with required `--lens` and `--language`, and optional `--root`, `--file` and `--profile`. The calibration file and the component bytes come from the installed saga (`parents[1]`, `plugins/saga` in a checkout and the plugin root in a marketplace copy). `--root` does not select that file. The profile is the base commit's: `--profile`, or `--root/.saga-profile.json` when `--root` is set, otherwise `.saga-profile.json` in the checkout that contains the script. Stdout is the one line from the design table. Stderr is empty on exit 0.

Apply KTD10's order. The pin comparison lazily imports `review_tools` and calls `load_tool_list(root / "plugins/saga/references/review-tools.yaml")`. It reads `.saga-profile.json` with the json module. It does not call `review_tools._pinned_version` or `_rules_for`. A row with an empty `tool` (coverage, the relocated test) is not a pin target. The no-run branch returns before the pin import, so the committed-file command does not load PyYAML. A profile is malformed when `review_tools._load_profile` would refuse it, as KTD9 lists, and that refusal exits 2.

Do not edit `review_formula.py`. The formula already accepts a `may_block` map from its caller. This unit does not build that map for a review run. C10a will call `may-block`.

`--help` goes through `argparse` and exits 0 before any file is read, so `test_entrypoints.py` picks the script up. The module must not import a third-party library at import time, or that test skips or fails.

## Risks & Dependencies

| Risk | Mitigation |
|---|---|
| A reader bug answers `yes` when no run exists, and an uncalibrated lens blocks. | No-run is the first branch. A malformed file exits 2. The committed file is `no-run`. One test covers every lens. Nothing calls `may-block` until C10a. |
| `check_repo.py` grows a second fingerprint, or imports PyYAML and fails on a machine that only has the standard library. | One function. `ReviewCalibrationTests` monkeypatches `review_calibration.check` and requires `check_repo` to surface the sentinel. A subprocess asserts `yaml` is not loaded by the repository check. |
| The ten literals drift away from `review_tools.FINGERPRINT_COMPONENTS`. | A test compares the slices. The existing text search in `test_fingerprint_names_these_paths` stays as it is. |

| The identifier pattern rejects a real Langfuse run id or model version when K3 first writes one. | The pattern allows letters, digits and `._:/-`. The decision says to revisit when a real id does not fit. Until then the committed file uses `null`. |
