# Pattern checks for the defects we keep hitting (issue #154)

## Summary

Six Semgrep rules, one per recurring defect in the correctness lens table. Each carries its harm and blocks merge unless the builder records a reason. C4a's adapter runs them on changed lines, setup asks each repository for its shared update paths, and CI installs the pinned Semgrep so the rule tests run on every pull request.

---

## Problem Frame

Issue #154 is card C5 of the #147 program, the saga code review redesign. It implements plan.md Change 4 ("Our own checks for the bugs we keep hitting") for the six pattern checks the correctness lens table names, so a deterministic check reports these defects instead of a reviewer arguing them.

What is true today: saga ships no pattern rules, Semgrep sits in the tool list unpinned and uninstalled, and the plugin-tests job installs only `requirements-plugin-tests.txt`, which does not list it. This card adds the rules with their rule tests, wires them through C4a's Semgrep adapter and changed-line filter, registers the shared-update-path question through C3's setup mechanism, pins and installs Semgrep, and fingerprints the rule files with C2. All four dependencies already landed in this tree: C1's pattern rows and validator, C3's extension registry, C4a's adapter, and C2's component list.

## Key Technical Decisions

- **KTD1. The rules live at `plugins/saga/references/semgrep/`, and C4a's `semgrep-rules` path is renamed to match.** AC-3 and the Verification block name that path literally and will be run verbatim, while C4a's name was chosen before the card text was reconciled. The rename touches the yaml row, the runner constant and its two read sites, two doc mentions, and the C4a tests asserting the literal. The issue #191 property survives it: the directory is still the installed plugin's, never the reviewed tree's. Rejected: keeping `semgrep-rules` and letting AC-3's literal command fail.
- **KTD2. Rule ids are `saga.<file-stem>`, `metadata.row` is C1's identifier from the table, and `metadata.harm` is the exact harm string from the table.** The C4a fixture already anticipates `saga.`-prefixed check ids, the adapter refuses a saga row outside C1's identifiers, and the validator accepts only the closed harm list, so a bad harm fails closed at emit time. The outcome follows from the formula row both cite (blocks, excused by `pattern-check`), kept in step by test. Rejected: bare-stem ids, which could collide with registry packs if configs ever combine, and prose harms, which the validator would refuse.
- **KTD3. Five rules cover Python and TypeScript; naive-time-comparison covers Python only.** The program's fix-history survey concentrates occurrences in Python, then TypeScript and Dart; the seeded naive-time fixture is Python datetime, and the one known shared write path is Python. TypeScript naive-date shapes and Dart, shell, Swift, and Rust coverage are later items once corpus evidence names them. Rejected: covering every saga language now, since rules without fix-history evidence risk false matches that block after calibration.
- **KTD4. The shared-update rule ships with an inert default alternation its rule tests exercise, and the runner swaps it for the profile's names.** Semgrep has no variable interpolation, so the names enter by exact-string substitution of the default block before the run. Without the key the runner substitutes a never-matching pattern and records the degraded input, so the rule still runs and still cannot block. Rejected: skipping the rule without the key, since the card says it runs degraded, and baking one repository's names into the shipped file, since per-repository config does not belong in the plugin.
- **KTD5. Substitution happens in the runner's rule-config resolution for the saga row only, into a fresh directory under the runner home.** The inputs are installed-plugin bytes plus the base-commit profile, both trusted, and the rendered directory never touches the reviewed tree. Head edits to the new key join the existing head-profile-change note. Rejected: rendering in the adapter's invoke, which never sees the profile, and rendering into the reviewed tree, where head content would configure its own review.
- **KTD6. The setup question registers in `setup-extensions.yaml` with key `review` and profile key `review`, storing `{"shared_update_paths": {language: [names]}}`.** C3's mechanism writes whole top-level keys and forbids later cards from editing the setup script, so the card's dotted proposal maps to this nested object. The runner treats a missing, empty, or non-mapping key as absent (degraded), never a crash, since setup stores extension answers unvalidated by design. Rejected: a flat top-level key, which loses the `review` namespace later review questions share.
- **KTD7. Semgrep pins at 1.179.0, the newest stable on the package index when this plan was written, identically in both yaml rows and the CI install, with a test asserting equality.** One binary means one pin, and may-block compares each row against that same pin. The implementer takes a newer stable only if this one is gone, moving all copies together. Rejected: leaving `default_version` not-recorded, since AC-4 needs a pin to install.
- **KTD8. The fingerprint lists the six rule files, not the directory.** C2's contract says a component is a file and anticipated exactly this ("the card that adds those checks lists the files"). Rule-test files and recorded fixtures stay out because they never change a review outcome. This is AC-10's "added here" branch; C2 already landed.

## Implementation Units

### U1. Pin Semgrep and install it in CI

One version, pinned in the tool list and installed by the plugin-tests job.

**Goal:** Semgrep resolves to a single version everywhere: both Semgrep rows of the default tool list and the CI install agree, and the plugin-tests job installs it.

**Requirements:** R7.

**Dependencies:** none.

**Files:** `plugins/saga/references/review-tools.yaml` (modify); `requirements-plugin-tests.txt` (modify); `.github/workflows/ci.yml` (modify only when the requirements route clashes); `plugins/saga/tests/test_pattern_checks.py` (create: the pin test).

**Approach:** Set `default_version` to the KTD7 pin on the `semgrep-security` and `semgrep-saga` rows. Add the exact pin to `requirements-plugin-tests.txt` first, per the install comment in the workflow; the implementer resolves that file once, and only when its pins clash does a step in the plugin-tests job install Semgrep into an environment of its own instead. The test finds the pin in exactly one install site and asserts it equals both rows' `default_version`, and the yaml still loads through the runner's tool-list loader.

**Patterns to follow:** the exact-pin rows C4b added to the yaml; the plugin-tests install comment in the workflow; the `_load` house pattern saga tests use to import scripts by path.

**Test scenarios:** Happy path — the pin in the install site equals both yaml rows. Edge cases — the pin lives in the workflow step instead of the requirements file and still matches; the two yaml rows disagree and the test names both. Error paths — the yaml fails schema load, naming the file; the install site names no Semgrep pin at all. Integration scenarios — none local prove the CI install; CI itself runs the file, and the Semgrep-dependent tests skip locally without the pin while naming the version found.

**Verification:** The new test file passes; the tool list loads; the requirements file resolves with the pin included.

### U2. Six rules and their rule tests

The rules, their metadata, and one rule-test file per language, all passing `semgrep --test`.

**Goal:** Each defect in the table has a rule carrying its harm and outcome, and rule tests pinning both what matches and what must not.

**Requirements:** R1, R2.

**Dependencies:** U1.

**Files:** `plugins/saga/references/semgrep/release-shares-cleanup-block.yaml` (new); `plugins/saga/references/semgrep/swallowed-error.yaml` (new); `plugins/saga/references/semgrep/silent-skip.yaml` (new); `plugins/saga/references/semgrep/write-skips-shared-update-path.yaml` (new); `plugins/saga/references/semgrep/naive-time-comparison.yaml` (new); `plugins/saga/references/semgrep/money-as-floating-point.yaml` (new); eleven rule-test files `<stem>.test.<ext>` beside them (new); `plugins/saga/tests/test_pattern_checks.py` (extend: the static and Semgrep parts).

**Approach:** Each rule carries id `saga.<file-stem>`, a one-sentence message, its table languages, and metadata keys `lens`, `defect`, `harm`, `outcome`, and `row` per the table. Rule-test files pair with their rule by Semgrep's `<stem>.test.<ext>` naming and are written fresh; nothing is copied from a private repository. Each rule's `ok:` lines pin the innocent lookalikes the author considered (a logged re-raise, a reached cleanup, an aware-datetime comparison, an integer-cents amount). The shared-update rule carries the inert default alternation and its exact substitution anchor from KTD4. Tests and the adapter invoke Semgrep with `--metrics=off` and `SEMGREP_ENABLE_VERSION_CHECK=0`.

**Patterns to follow:** the `saga.`-prefixed check id in the C4a saga fixture; the seeded naive-datetime fixture for the defect shape (read, never copied); the board-write guards for the shared-path instance this repository will name.

**Test scenarios:** Happy path — every rule file parses with PyYAML and carries its id, message, languages, and metadata harm and outcome; every table language has a test file with at least one `ruleid:` line and one `ok:` line; each cited formula row has outcome blocks excused by `pattern-check`. Edge cases — a statement spanning two lines fails the one-line check; a rule-test file missing either marker fails naming the file. Error paths — without Semgrep at the pin the Semgrep part skips and names the version found. Integration scenarios — `semgrep --test` passes over the rules folder with metrics and the version check off and sockets refused, so no network call is made.

**Verification:** The card's literal `semgrep --test` command passes at the pin; the extended test file passes with and (by skipping) without the binary.

**Functional checks:**


### U3. Adapter and runner wiring

C4a's adapter runs the rules on changed lines, renders the shared-update names, and degrades without the key.

**Goal:** A match on a changed line becomes a validated correctness finding that blocks unless excused, and the profile key drives the shared-update rule or its degraded input.

**Requirements:** R3, R4, R5.

**Dependencies:** U1, U2.

**Files:** `plugins/saga/scripts/review_tools.py` (modify); `plugins/saga/scripts/review_adapters_all_languages.py` (modify); `plugins/saga/references/review-tools.yaml` (modify: the saga path); `plugins/saga/tests/fixtures/review_tools/semgrep-pattern-checks.json` (new); `plugins/saga/tests/test_pattern_checks.py` (extend: the adapter part); `plugins/saga/tests/test_review_adapters_all_languages.py` and `plugins/saga/tests/test_review_tools.py` (modify: the path literal).

**Approach:** Rename the saga path in the yaml row, the runner constant and its two read sites; the C4a tests asserting the literal move with it. The saga parser reads `metadata.harm` onto the hit, and finding construction copies it to the finding's consequence; anything outside the closed harm list fails C1 validation at emit time, which refuses the run. For the saga row only, rule-config resolution renders the six rule files into a fresh directory under the runner home: the shared-update rule's default anchor becomes an alternation of the profile's names, each regex-escaped, or a never-matching pattern with reason `missing-shared-update-paths` when the key is missing, empty, or not a mapping. The profile comes from the base blob, and head edits to the new key join the head-profile-change note. The new fixture holds one recorded result per rule and leaves C4a's fixtures untouched.

**Patterns to follow:** the C4a recorded-output adapter tests; the formula outcome tests for blocks and excused reasons; the runner's degraded-input and head-profile-change shapes.

**Test scenarios:** Happy path — each rule's recorded output becomes a correctness finding citing its row, carrying the rule identifier and harm and no severity, and passes C1 validation; through the formula it blocks, and with a `pattern-check` reason against its identity it drops to a note. Edge cases — a reason recorded against another finding's identity leaves the finding blocking; profile names containing regex metacharacters match literally; a rule result on an unchanged line yields nothing. Error paths — no usable key records the degraded input and the rendered rule reports nothing that can block; a non-mapping or empty key takes the same path without crashing; a head-only key change keeps the base value and records the head-profile-change note. Integration scenarios — the renamed C4a tests still prove the untrusted-commit handling end to end.

**Verification:** The extended test file passes; the C4a adapter and runner suites pass with the new path.

## Risks & Dependencies

Dependencies, all met in this tree: C1's pattern rows, harm list, and validator (`review_formula.py`, `review_records.py`); C3's extension registry (`setup-extensions.yaml`, with C5's question explicitly anticipated); C4a's saga adapter, changed-line filter, and default tool list; C2's component list, whose doc anticipates this card listing the rule files.

- A rule matching correct code would block merges once the correctness lens clears calibration. The rule tests pin both directions, a builder can record a reason for a false match, and until calibration every lens only reports.
- The money-as-float and TypeScript patterns lean on naming heuristics. Each rule's `ok:` lines pin the innocent lookalikes, and narrow patterns beat broad ones; corpus misses widen them later.
- Semgrep 1.179.0 could be gone when the implementer runs. The equality test holds whatever stable is taken, since all copies move together.
- Appending components is inert while the calibration file records no run; the first recorded run fingerprints the new files, and from then on a rule edit without a fresh corpus run fails the repository check.
