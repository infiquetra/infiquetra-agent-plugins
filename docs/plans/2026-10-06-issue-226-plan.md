# Saga survey detection for pytest plugins, muter, and the pinned ruff runner (issue #226)

## Summary

Saga's setup survey probes pytest plugins as PATH executables that do not exist, rejects muter's bare `16` version, and runs ruff from PATH at whatever version the operator holds. This plan marks run-time-loaded rows to probe the uv loader instead of PATH, shares one version grammar between survey and review, and runs the ruff adapter through `uv run --with ruff==0.15.18`.

---

## Problem Frame

This is a defect against the saga review redesign (parent issue #147), found while installing saga's review tools for the review corpus harness, which refuses a full run while any default tool reads as not installed. Three survey rows report wrong, and one row hides a real version conflict.

First, pytest-randomly and pytest-socket are pytest plugins with no console script, but the survey probes each row as a PATH executable (`plugins/saga/scripts/saga_setup.py:425`), so both read `missing` forever. The review already loads both per run through `uv run --with pytest-randomly==5.0.0` and `uv run --with pytest-socket==0.8.1` (`plugins/saga/scripts/review_adapters_python.py:546-553`), so nothing needs installing; the row is wrong. A live survey on this machine confirms it: the pytest-randomly row reads `missing` with no executable involved.

Second, muter prints a bare `16` for `--version`, but the survey's version pattern requires at least two dotted parts (`plugins/saga/scripts/review_tools.py:63`, used at `plugins/saga/scripts/saga_setup.py:436`), so an installed muter reads as missing. The review's own run-time check already solved this with a whole-output rule for bare integers (`plugins/saga/scripts/review_tools.py:1204-1218`); the survey never adopted it.

Third, the ruff adapter runs `ruff check` from PATH (`plugins/saga/scripts/review_adapters_python.py:382-387`), so a review's findings depend on the operator's ruff. The pin is 0.15.18 and the operator holds 0.16.9 for other work. Worse, the run-time version check marks off-pin tools degraded (`plugins/saga/scripts/review_tools.py:797-799`), so PATH 0.16.9 both changes the findings and degrades the lens.

One naming note: the card's file list names `plugins/saga/references/review-tools.json`. No such file exists; the tool list is `plugins/saga/references/review-tools.yaml`. Every Files entry below uses the real name.

## Requirements

Requirements are grouped by concern; R-IDs run continuously.

**Pytest plugin rows**

- R1. The survey reports the pytest-randomly and pytest-socket rows installed at their pins when the uv loader answers with exit 0 and a version, and missing when uv is absent, fails, or answers versionless; it never probes for plugin-named executables on PATH (AC-2).
- R2. A profile pin that differs from the row default on a run-time-loaded row reads wrong-version at the row default the adapter loads, so a pin the adapter cannot honor stays visible instead of reading installed (AC-2).

**Bare-integer versions**

- R3. The survey accepts a bare-integer `--version` answer (muter prints `16`) and compares it against the pin; dotted parsing is unchanged, and a bare number buried in longer output still reads missing (AC-2).

**Pinned ruff**

- R4. The Python review adapter runs ruff through `uv run --with ruff==<pin>` at the ruff-lint row's pin (0.15.18), and its run-time version probe checks that pinned runner, so ruff 0.16.9 on PATH neither changes the findings nor degrades the lens (AC-1).
- R5. The survey's ruff-lint and ruff-format rows report installed at the pin when the uv loader answers with exit 0 and a version, and missing when it is absent, fails, or answers versionless; PATH ruff's version is no longer reported as a review problem (AC-1).

**Preservation and proof**

- R6. Every other survey row keeps its status for the same machine state (AC-3).
- R7. All new tests prove detection and the pinned runner with stub runners only: no test installs, upgrades, downloads, or removes a tool, and nothing edits PATH or dotfiles (brief rule; AC-1, AC-2). The one touched live test runs only when the pin is already in the uv cache, proven by an offline probe, and otherwise skips with a stated reason.

**Changelog and journal**

- R8. The changelog's Unreleased Fixed section names issue #226; the saga plugin version is untouched; the engineering journal records the detection lesson (repo rules; no AC).

## Key Technical Decisions

Each entry is the decision, then why, naming what was rejected.

- **KTD1. Run-time-loaded rows probe the loader, not the tool.** A row with `runtime_loaded: true` in `review-tools.yaml` runs `uv --version` as its probe and, when the loader answers with exit 0 and a version parsed from its output, reports installed at the pin through the existing `_classify` comparison — so a differing profile pin reads wrong-version (R2) with no new comparison logic. Absent, timed-out, non-zero, or versionless loader output reads missing: a failed or versionless uv is never installed. The question the row answers changes from "is it on PATH?" to "can the review load it pinned?", which is the only question that matters for tools the adapter loads per run. Rejected: counting any spawned `uv --version` as answering (an errored input counted as installed is the card's hides-a-missing-tool risk); probing `uv run --with <pkg>==<pin>` in the survey (fetches from the network inside a read-only survey and duplicates the adapter's resolution); an ambient importlib probe (the wrong environment — the adapter uses an ephemeral uv env, so ambient absence proves nothing); marking the rows installed unconditionally (hides a missing uv, the loader the review needs).
- **KTD2. The survey reuses `review_tools._found_version`: dotted anywhere, else a bare integer only as the whole output.** The run-time check's grammar is already reviewed and carries the whole-output guard that keeps build counts and warning tallies from reading as versions; sharing it means the survey and the review can never disagree on what counts as a version. `saga_setup.py` already imports the sibling private `_VERSION` from the same module, so the reuse follows existing practice. Rejected: loosening the `_VERSION` regex (a bare number anywhere in longer output would read counts as versions); a muter-only special case (duplicates the rule the run-time check already owns).
- **KTD3. The ruff scan prefixes its inner command with `uv run --with ruff==<pin>`, the pin threaded from the ruff-lint row at build time, and the run-time probe checks the same pinned runner.** The argv shape mirrors the cosmic-ray and pytest precedents (`uv run --with <pkg>==<pin>` with no extra flags); threading the pin through `_build` beside the ruff family map keeps one pin source so the yaml edit moves scan and probe together. The probe must move with the scan: a PATH probe would still report 0.16.9 against the 0.15.18 pin and degrade the lens the scan just fixed. The ruff-lint row stays non-narrow since both run environments pass PATH through, so uv resolves either way. Rejected: a hardcoded pin in code (drifts from the yaml row); keeping the PATH probe (preserves the degraded lens on the operator's machine); honoring profile pins in invoke (invoke functions never see the profile — cosmic and pytest hardcode theirs too — so profile pins keep their existing check-only role, and changing that would widen the card).
- **KTD4. Both ruff survey rows move to the loader probe; the ruff-format adapter stays untouched.** Both rows report PATH ruff's version today, so leaving ruff-format on the PATH probe preserves the exact conflict the card removes. The adapter needs no change: fix-mode adapters never run in review or the build loop (`review_tools.py:600`), and ruff-format already invokes nothing. Rejected: moving only the ruff-lint row (the survey would still nag about PATH ruff's version on the ruff-format row).
- **KTD5. Stub-only proof; no live test downloads the pin.** A stub uv on PATH records the invoked argv and answers the probe, which proves the adapter runs the pinned runner without fetching anything; the suites' existing no-network fixtures stay in force. Rejected: a live `uv run --with ruff==0.15.18` test (fetches the pin into the uv cache on first run — an install-shaped side effect the brief forbids, for no signal the stubs do not give).

## Implementation Units

Four units: the run-time-loaded survey rows, the bare-integer version grammar, the pinned ruff runner with its survey rows, then the changelog and journal.

### U1. Run-time-loaded survey rows for the pytest plugins

The two pytest plugin rows stop probing PATH for executables that do not exist and instead probe the uv loader that the review uses.

**Goal:** pytest-randomly and pytest-socket survey as installed at their pins when uv answers with exit 0 and a version, and missing on any loader failure, with every other row's status pinned by a golden test.

**Requirements:** R1, R2, R6, R7.

**Dependencies:** none.

**Files:** `plugins/saga/scripts/saga_setup.py` (modify: the run-time-loaded branch in `_probe_row` at `:400-457`); `plugins/saga/references/review-tools.yaml` (modify: `runtime_loaded: true` on the pytest-randomly and pytest-socket rows at `:334-359`); `plugins/saga/tests/test_saga_setup.py` (modify: loader tests and the AC-3 golden test).

**Approach:** Add `runtime_loaded: true` to the two pytest plugin rows. In `_probe_row`, right after the empty-tool guard, branch on the marker: run `uv --version` through the injected runner with the row's timeout, requiring exit 0 and a version parsed from the output with the shared `_found_version` grammar. FileNotFoundError, a timeout, a non-zero exit, or versionless output reads missing; only a clean versioned answer reports installed through the existing `_classify` against the row default the adapter loads, so a differing profile pin reads wrong-version (R2) with no new comparison code. The row's `tool`, `has_install`, and pane display stay as they are. New tests are named `test_survey_runtime_loaded_*` so the functional check selects them with `-k` (exit 5 if never added). The AC-3 golden test, named `test_survey_status_golden_freezes_untouched_rows`, runs the shipped tool list with a deterministic stub runner (PATH tools answer fixed versions, uv answers with exit 0 and a version) and asserts the exact pre-change status of every row outside the five this card touches; it is written from current behavior and may only change when a later card intentionally changes a row.

**Patterns to follow:** `plugins/saga/tests/test_saga_setup.py:75-78` (`_tools`, the fixture yaml writer); `plugins/saga/tests/test_saga_setup.py:140-157` (`_happy_runner`, the stub-runner double with per-argv answers); `plugins/saga/tests/test_saga_setup.py:56-62` (the no-network fixture, still in force); `plugins/saga/scripts/saga_setup.py:374-386` (`_classify`, reused unchanged).

**Test scenarios:**

- Happy path: with stub uv answering exit 0 and `uv 0.0.0`, both plugin rows read installed with versions `5.0.0` and `0.8.1`; the stub records no `pytest-randomly` or `pytest-socket` argv (no PATH probe ran).
- Absent loader: with uv raising FileNotFoundError, both rows read missing; a uv timeout reads missing too.
- Failed or versionless loader: a non-zero `uv --version`, empty output, and output with no version each read missing, never installed.
- Marker is the switch: the same tool list with the marker removed still probes PATH and reads missing, so the change cannot blanket-mark rows installed.
- Profile pins: a profile pin equal to the row default reads installed; a differing profile pin reads wrong-version at the row default the adapter loads.
- Golden preservation: every shipped row outside the five touched reads its pre-change status under the deterministic stub runner (AC-3).
- Yaml pin: exactly the pytest plugin rows carry `runtime_loaded: true` after this unit (the full four-row set is pinned in U3).

**Verification:** the targeted checks below pass with the loader tests and the golden test in them; the direct survey below shows both rows installed at their pins with only a stub uv on PATH and no plugin executable anywhere.

**Functional checks:**

```functional-checks

  proves: [AC-2]
  runs: local
- name: survey-preservation-golden
  command: python3 -m pytest plugins/saga/tests/test_saga_setup.py -q -k survey_status_golden

  proves: [AC-2]
  runs: local
```

### U2. Bare-integer versions in the survey

Muter's bare `16` stops reading as missing, under the same grammar the review's run-time check already uses.

**Goal:** The survey parses bare-integer `--version` output and compares it against the pin, with the whole-output guard and dotted parsing unchanged.

**Requirements:** R3, R6, R7.

**Dependencies:** U1 (both units edit `_probe_row`; land in order so the golden test reruns against the new grammar).

**Files:** `plugins/saga/scripts/saga_setup.py` (modify: the version parse at `:436` uses `review_tools._found_version`); `plugins/saga/tests/test_saga_setup.py` (modify: bare-version tests). No yaml change: the muter row already pins default_version `"16"` at `plugins/saga/references/review-tools.yaml:1270`.

**Approach:** Replace the `_VERSION.search(text)` call in `_probe_row` with `review_tools._found_version(text)` (KTD2) and drop the now-unused module `_VERSION` import if nothing else uses it. Everything downstream — `_classify`, the display pin, the gh special case — stays untouched: `"16" == "16"` reads installed through the exact path, and single-component versions already flow through `_at_least` for minimum-mode rows. The muter row needs no marker and no other edit. New tests are named `test_survey_bare_integer_*` so the functional check selects them with `-k` (exit 5 if never added).

**Patterns to follow:** `plugins/saga/scripts/review_tools.py:1204-1218` (`_found_version`, the grammar with its whole-output rule); `plugins/saga/scripts/saga_setup.py:31-38` (the module already imports `review_tools` and its `_VERSION`); the U1 stub-runner patterns for per-argv `--version` answers.

**Test scenarios:**

- Happy path: stub muter printing `16` reads installed with version `16` against the shipped pin.
- Wrong version: stub muter printing `15` reads wrong-version against pin `16`.
- Dotted unchanged: `1.2.3` and `1.2` outputs still parse to the dotted version.
- Whole-output guard: a bare number buried in longer output (for example a warning tally) reads missing, not that number.
- Garbage: empty output and output with no number at all read missing.
- Preservation: the U1 golden test reruns green against the new grammar, proving no other row changed status (AC-3).

**Verification:** the targeted check below passes with the bare-version tests in it; the direct survey below shows the muter row installed at `16` with only a stub muter printing `16` on PATH.

### U3. The pinned ruff runner and its survey rows

The review runs ruff 0.15.18 through uv no matter what PATH holds, and the survey stops reporting PATH ruff's version as a review problem.

**Goal:** The ruff-lint adapter scans and probes through `uv run --with ruff==0.15.18`, and both ruff survey rows use the U1 loader mechanism.

**Requirements:** R4, R5, R6, R7.

**Dependencies:** U1 (the ruff survey rows use the run-time-loaded mechanism).

**Files:** `plugins/saga/scripts/review_adapters_python.py` (modify: `_invoke_ruff` at `:382-387` takes the pin and prefixes `uv run --with ruff==<pin>`; `_build` at `:619-667` threads the pin from the ruff-lint row and builds the pinned `version_argv` beside the family map); `plugins/saga/references/review-tools.yaml` (modify: `runtime_loaded: true` on the ruff-lint and ruff-format rows at `:260-295`); `plugins/saga/tests/test_review_adapters_python.py` (modify: pinned-runner tests); `plugins/saga/tests/test_saga_setup.py` (modify: ruff-row survey tests).

**Approach:** In `_build`, read the ruff-lint row's `default_version` and pass it to a `_invoke_ruff(pin)` factory returning `["python3", "-c", _RUFF_WRAPPER, "--", "uv", "run", "--with", f"ruff=={pin}", "ruff", "check", "--isolated", ...]` — the cosmic-ray argv shape, with the scan root still last so the wrapper keeps relativizing paths. Build the ruff-lint `version_argv` there too as `("uv", "run", "--with", f"ruff=={pin}", "ruff", "--version")`, passed through the existing `_from_row` parameter the pytest adapters already use. Mark both ruff yaml rows `runtime_loaded: true` so the survey probes the loader (KTD4). The ruff-format adapter, the ruff wrapper, the finding parser, and the row's narrow setting stay untouched. The existing live ruff test is gated on the pin already being in the uv cache: a module helper probes `uv run --offline --with ruff==<pin> ruff --version` (the pin derived from the adapter, `--offline` forbidding any network) and the test skips with a stated reason unless the probe exits 0 reporting the pin — so the suite never downloads the pin. New adapter tests are named `test_pinned_ruff_*` and new ruff-row survey tests `test_survey_runtime_loaded_ruff_*`, so each functional check selects them with `-k` (exit 5 if never added).

**Patterns to follow:** `plugins/saga/scripts/review_adapters_python.py:506-509` (the cosmic-ray `uv run --with` argv shape); `plugins/saga/scripts/review_adapters_python.py:629-633` (the family map threaded through `_build`, the pin's precedent); `plugins/saga/scripts/review_adapters_python.py:46-55` (the `_VERSION_ARGV` mechanism the ruff probe joins); `plugins/saga/tests/test_review_adapters_python.py:100-113` (`_version_text`, the stub-process version answers to extend for the uv probe).

**Test scenarios:**

- Happy path: with PATH ruff answering `0.16.9` and the pinned probe answering `0.15.18`, the scan argv starts with `uv run --with ruff==0.15.18`, findings parse onto the ruff rows, and no version-mismatch degraded input is recorded.
- Pin argv: the invoked argv contains exactly `ruff==0.15.18`, asserted equal to the ruff-lint row's `default_version` so code and yaml cannot drift.

- Live gate: the live ruff test skips with a stated reason when the pin is not in the uv cache (no network attempted), and runs the pinned adapter end to end when it is; the family-level mapping, isolated select-all, and decoy-config tests keep passing unchanged.

## Risks & Dependencies

| Risk | Mitigation |
|---|---|
| A wrong detection hides a genuinely missing tool (the card's stated medium risk). | Loader rows read missing when uv is absent, failing, or versionless; the marker-is-the-switch test proves unmarked rows still probe PATH; the whole-output guard test proves tallies do not read as versions. |
| `uv run` fetches the pin from the network on first use in a fresh-HOME review. | The cosmic-ray and pytest adapters already pay exactly this cost with the same argv shape; the survey itself never fetches (it runs only `uv --version`). |
| A profile pin the adapter cannot honor could read installed. | R2 routes loader rows through `_classify`, so a differing profile pin reads wrong-version in the survey and degrades at run time — the mismatch stays visible in both places. |
| The corpus harness gate is private, so the "full run proceeds" outcome cannot be verified here. | The survey statuses are the contract the gate reads; AC-2 and AC-3 pin them row by row, and the direct-survey checks prove them the way the harness runs them. |
| U1 and U2 edit the same probe function. | U2 depends on U1 and reruns the golden test against the new grammar, so the shared-parser change cannot silently move another row. |

Depends on #150 (landed: the survey and its probe structure) and #152 (landed: the Python adapters and their `uv run` precedents). Hands a truthful survey and a pinned ruff run to the corpus harness's first full run.
